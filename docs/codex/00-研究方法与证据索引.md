# 研究方法与证据索引

## 1. 研究目标

本次研究目标是建立足以指导独立复刻的产品事实基线，具体包括：

- 枚举当前账号可访问的所有全局导航、列表、详情、工作台和隐藏路由；
- 还原普通漫剧从剧本到视频的端到端生产链；
- 还原新闻播报模板的配置、阶段、产物和交付方式；
- 提取可观察的数据模型、API 形态、状态枚举、轮询策略和技术栈；
- 识别权限边界、积分结算、高成本操作、自动保存和失败补偿风险；
- 将事实、推断和复刻建议分开，避免把未知项写成既定事实。

## 2. 研究边界

### 2.1 允许的操作

- 使用授权账号登录；
- 导航页面、切换标签、搜索、展开下拉、打开只读详情和预览；
- 打开确认框后取消；
- 读取页面可访问性树、截图、控制台和网络请求；
- 只读下载并分析浏览器已加载的前端静态资源；
- 访问应用前端已声明、且当前账号可读取的路由。

### 2.2 禁止的操作

- 创建、保存、编辑、删除或发布线上业务数据；
- 上传素材、通过/驳回审核、分配积分、调整账号或组织权限；
- 主动调用写 API、绕过权限或探测其他租户；
- 批量下载用户内容、破解前端或获取服务端源码；
- 将登录凭据、Cookie、令牌、真实项目名称、真实 UUID 或动态余额写入正式文档。

### 2.3 意外写请求说明

调研中发生两类意外写请求，均如实纳入风险分析：

1. `E1` 现场记录：在点击“分镜生成”以确认交互时，按钮没有二次确认，立即创建了生成作业。作业经历 `queued -> running -> failed`，平台预占积分并在失败后自动释放。未生成可用产物，也未继续重试；本地原始证据中没有保存该请求/响应，不能升级为完整网络取证。
2. `E2/E3` 在画布进行节点选择或尺寸菜单探索后，网络中出现一次 `PATCH /materials/{material_id}/canvas/delta`。没有修改提示词、节点位置或表单，也没有点击保存；因未保留请求体，无法判断写入的是选择/视口等 UI 瞬态，还是业务数据增量。

这两件事说明：原站存在“表面只读交互可能触发写操作”的产品与审计风险。复刻产品必须将成本确认、脏状态、自动保存范围、撤销和审计作为显式能力。

## 3. 研究方法

### 3.1 页面遍历

按“全局入口 -> 列表 -> 卡片/行 -> 详情 -> 标签/筛选 -> 弹窗/空态 -> 返回路径”遍历。每次重大 DOM 变化后重新获取可访问性快照，以避免使用过期控件引用。

### 3.2 网络观察

记录页面自然产生的 GET 请求、一次误触作业请求和一次疑似画布自动保存请求。API 字段仅在页面响应、浏览器网络记录或前端调用代码中出现时标为 `E2`。

### 3.3 前端静态分析

对浏览器已加载的 Vite bundle 进行字符串和调用点检索，确认：

- 前端路由与隐藏页面；
- API 基础路径和端点模板；
- 模型、比例、分辨率、数量和素材数量校验；
- 查询轮询周期与异步作业状态；
- 关键请求体字段和前端技术依赖。

静态分析只能证明“当前前端包含或调用该能力”，不能证明服务端所有分支都可用。

### 3.4 多代理交叉核验

探索被拆成三个互相独立的业务方向：

- 项目、剧本、分集、主体和资产；
- 创作画布、分镜、镜头组、视频生成和新闻播报；
- 视频版本、时间线、积分、账号、组织和权限。

主会话另行检查完整路由、关键 API、模型规则和重复结论。离线审计代理只检查证据覆盖与敏感信息，不访问网站。

## 4. 证据等级

| 等级 | 判定标准 | 可以支持的结论 | 不能支持的结论 |
| --- | --- | --- | --- |
| `E1` | 浏览器真实显示或交互结果 | 页面存在、控件文案、可见状态、可访问路径 | 服务端内部实现、其他角色权限 |
| `E2` | 网络、响应结构或前端代码直接出现 | 接口形态、字段、枚举、校验、技术依赖 | 未执行接口的成功行为、数据库实现 |
| `E3` | 多个 E1/E2 事实共同指向 | 领域关系、后端职责、产品意图 | 需要服务端源码或管理员验证的事实 |
| `D` | 独立复刻的目标设计 | 推荐架构、安全和体验要求 | 原站事实 |
| `U` | 样本或权限不足 | 后续验证清单 | 任何确定性承诺 |

### 6.1 证据规模与敏感边界

离线审计共确认 196 个证据文件，约 10 MB：122 个可访问性 YML、31 个文本记录、14 个 JSON、7 个控制台日志和 22 张 PNG。四个方向分别为项目资产 81、制作画布 39、主会话 40、发布权限 36。

- 14 份 JSON 均可解析，无空文件；
- 22 张截图均为 1200x870，不能支持移动端或其他桌面宽度结论；
- 大多数快照和截图可识别真实账号、项目内容或动态业务数据；
- 多份文本含 UUID，少数流水/快照含疑似手机号形态数字；
- 积分流水响应同时含操作者、目标账号、来源实体、业务关联 ID 和动态余额，敏感度最高；
- 未发现登录密码、JWT、私钥、Authorization、Cookie 或 Set-Cookie 的实际值落盘。

因此整个 `output/playwright/` 都按本地敏感原始证据处理。若未来需要对外展示截图，必须生成遮罩后的派生图，至少遮盖账号、积分、项目标题、正文、主体、内部 ID 和存储地址。

## 7. 技术证据摘要

### 7.1 前端与运行环境

- `E2` Vite 构建的 React 19 单页应用；
- `E2` React Router 负责路由；TanStack Query 负责服务端状态；
- `E2` Axios 风格请求封装；
- `E2` Tailwind CSS、Radix/shadcn 风格组件、Tabler Icons、Sonner Toast；
- `E2` dnd-kit 用于可排序交互，GSAP 用于动画；
- `E2` 画布独立 bundle 体积较大，具备复杂节点编辑能力；
- `E2` 应用基础路径 `/v3/`，API 基础路径 `/v3api`；
- `E2` 响应头显示 IIS，但这不能证明后端一定使用 .NET。

### 7.2 轮询

| 对象 | 观察周期 | 风险 |
| --- | --- | --- |
| 积分账户 | 约 10 秒 | 页面静止时仍轮询，存在不必要流量 |
| 分析作业 | 排队/运行时约 1 秒 | 大规模任务会形成轮询风暴 |
| 剧本流水线 | 运行时约 1.5 秒，其他约 2.5 秒 | 应按可见性和状态退避 |
| 主体提取 | 约 2-3 秒 | 可合并到统一任务订阅 |
| 新闻播报 | 运行时约 1.5 秒 | 长任务适合 SSE/WebSocket 或自适应轮询 |

`D` 复刻时优先使用事件推送；若只能轮询，应采用页面可见性检测、指数退避、随机抖动和服务端批量状态接口。

### 7.3 错误与资源风险

- `E2` 一份视频控制台日志中，同一 `video-generation-jobs` GET 在 2.831 秒内产生 48 次 422，平均约 60ms 一次。它支持“错误重试或重渲染请求风暴”结论，但不支持确定具体前端根因。
- `E2` 观察到一次生成图片资源 404。复刻时需要稳定占位、失效资源状态和可控重试，不能无限重新请求。
- `E2` 账号管理相关接口在多个会话中重复 403。权限拒绝不应自动重试；路由进入前先读取能力声明，服务端仍独立鉴权。
- `E2` 资产列表一次加载出现逐剧本附加资产请求，支持 N+1 风险结论。

## 8. 已知样本限制

- `U` 只有一个普通成员账号，无法验证管理员、财务管理员、审核员或跨组织角色；
- `U` 团队项目为空，未验证多人编辑、团队资产、锁和冲突合并；
- `U` 未执行创建、保存、上传、审核、删除、取消、发布和最终合成；
- `U` 未主动构造 401/403/404/409/422/429/500、断网和对象存储失效；
- `U` 未验证移动端、窄屏、键盘无障碍、屏幕阅读器和国际化；
- `U` 未验证大分页、超长剧本、超多节点、超大素材和长时间运行；
- `U` 未验证内容安全审核、版权检测、敏感词、真人肖像授权和水印策略；
- `U` 未确认最终“发布”是否为独立模块；当前页面与入口覆盖至生成、编排和下载，但相关写流程未形成成功实测闭环。
- `U` 新闻播报只有创建配置、路由和前端阶段/产物代码证据，缺少成功详情页和最终视频的本地直接证据。

## 9. 结论可信度

页面结构、当前账号权限、普通制作主链路、新闻播报参数、视频生成素材限制和任务状态具有较高可信度；管理员能力、多人协作、最终发布、服务端技术栈和所有异常分支仍需在专门测试环境补证。复刻项目应把 `U` 项转化为产品决策，而不是等待逐字复制原站。

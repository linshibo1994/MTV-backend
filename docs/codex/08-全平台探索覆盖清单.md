## 1. 文档目的

本文回答四个问题：

1. 当前调研已经覆盖了哪些页面、控件、状态、接口、业务流程和权限边界。
2. 每项结论由什么级别的证据支持，证据位于何处。
3. 哪些能力只能视为推断、建议或未验证项，不能直接作为复刻事实。
4. 后续如何在不泄露数据、不误触高成本操作的前提下补齐证据。

本文中的“覆盖”仅表示调研证据完整度，不代表原平台功能质量，也不代表复刻产品已经实现。

## 2. 证据等级

| 标记 | 名称 | 定义 | 可支持的结论 |
|---|---|---|---|
| E1 | 页面直接实测 | 真实浏览器中的页面、可访问性快照、截图、控件状态或人工现场观察 | 页面结构、可见文案、交互入口、直接观察到的状态变化 |
| E2 | 网络/API/前端代码证据 | 网络列表、脱敏响应结构、控制台日志或另行保存的前端代码索引 | 接口路径、字段结构、状态码、枚举、轮询或前端实现机制 |
| E3 | 合理推断 | E1/E2 可以共同指向，但没有完成真实闭环验证 | 可能的业务意图、关联关系、后端职责边界 |
| D | 复刻建议 | 面向新产品的设计或工程建议 | 应如何实现，不表示原平台已经如此实现 |
| U | 未验证 | 当前没有充分证据，或仅有入口而没有结果 | 不得写成原平台既有事实 |

### 2.1 使用规则

- 一个结论同时有 E1 和 E2 时，正文应同时列出两类证据。
- 只有控件入口、没有成功结果时，最高只能写为“入口已确认”，不能写为“流程已验证”。
- 从 bundle、接口名称或字段名推导出的行为必须标 E2 或 E3，不能标 E1。
- 复刻建议必须与原平台事实分段书写，避免读者误认为建议来自实测。
- 新闻播报、账号管理、发布能力和所有写操作必须遵守本文的降级结论。

## 3. 覆盖强度判定

| 等级 | 判定条件 |
|---|---|
| 强 | 至少有直接页面证据，并覆盖主要控件、一个以上关键状态及对应读接口或数据结构 |
| 中 | 已进入页面并确认主要结构，但成功写流程、异常状态或接口契约至少缺一类 |
| 弱 | 只有入口、局部快照、单一错误日志或接口路径，无法还原完整页面和闭环 |
| 未覆盖 | 没有直接证据，或只有无法独立验证的推断 |

强覆盖不等于 100% 完整。只要高风险写操作、角色差异、响应式或异常恢复尚未验证，仍需在对应维度保留 U。

### 4.2 敏感边界

原始证据包含真实登录后界面、业务标题、业务描述、用户标识、组织字段、动态积分和内部业务标识。敏感扫描结论如下：

- 未发现已提供密码的明文落盘。
- 未发现 JWT、私钥、Authorization、Cookie 或 Set-Cookie 的实际值落盘。
- 大量文本快照包含真实账号标识；多数登录后截图也可通过 OCR 识别该标识。
- 多个文本文件包含真实业务 UUID。
- 少量文件含手机号形态数字，应按潜在个人信息处理，不判断其真实语义。
- 积分流水响应包含操作人、目标账号、业务来源和关联实体，属于高敏感原始证据。
- 剧本、主体、镜头和画布快照包含真实业务正文，禁止原文引用。

因此，`output/playwright/` 必须保持为本地、受限、非正式交付材料。正式文档必须引用稳定证据编号；存在本地证据时附相对路径，只有脱敏代码索引时明确说明无原始 bundle 路径。任何情况都不能复制原始响应、原图、真实示例值或完整可见文本。

### 4.3 重复证据处理

- 登录初始快照存在四个完全相同副本，统一引用 `EV-GLOBAL-LOGIN-01`。
- 剧本分集响应和资产页分集响应内容相同，统一由各自证据编号引用，但不重复统计字段覆盖。
- 资产详情顶部与一次“滚动后”快照内容完全相同，该副本不能证明真实滚动位置变化。
- 多个“正在验证登录状态”快照内容完全相同，只能证明中间加载态，不能证明后续页面结果。

## 15. 技术与产品风险

### 15.1 P0 风险

1. **视频任务错误请求风暴（E2）**：同一视频任务查询在约 2.8 秒内出现 48 次 422，平均约 60ms 一次。复刻时必须对参数合法性、查询启用条件、错误退避和最大重试次数做硬约束。
2. **高成本生成缺少二次确认（仅现场 E1）**：分镜生成误触后直接进入任务并发生积分预留。该事件没有原始网络文件，只能作为现场风险记录；复刻时仍应采用费用预估、确认、幂等键和取消窗口。
3. **原始证据泄露风险**：登录后快照、截图和 API 响应包含账号、积分、业务标识和正文。任何自动生成文档流程都必须先做脱敏扫描。

### 15.2 P1 风险

1. **资产列表 N+1（E2）**：一次列表加载对多个剧本逐一请求资产条目，网络证据中出现成组重复请求。建议使用批量封面/摘要接口或后端聚合。
2. **积分账户高频重复请求（E2）**：长时间捕获中出现大量重复账户请求。现有网络列表没有时间戳，不能只凭它断言精确间隔；复刻时应使用页面可见性、缓存、失焦降频和事件驱动刷新。
3. **权限失败后加载体验不完整（E1/E2）**：账号接口 403，同时留下“验证登录状态”加载快照。复刻时需要明确的无权限终态，禁止无限加载。
4. **媒体资源失效（E2）**：存在一次图片资源 404。需要失效占位、重签名、重试和不可恢复错误提示。
5. **搜索无结果与真实空态易混淆（E1）**：剧本/资产列表应区分“没有任何数据”和“筛选后无结果”，并提供不同恢复动作。

### 15.3 P2 风险

1. 可访问性快照不能证明键盘、焦点和对比度达标。
2. 所有截图均为单一桌面尺寸，复杂画布和表格在小屏上的行为未知。
3. 多个快照完全重复，自动取证应记录 URL、视口、页面状态和动作，避免用重复快照误判覆盖。

## 17. 未来补证安全操作规程

### 17.1 前置条件

1. 仅使用获得明确授权的测试租户、测试账号和虚构业务数据。
2. 测试账号设置单次和单日费用上限，不使用生产积分账户。
3. 高风险操作前确认可逆性、预计费用、取消条件和清理方式。
4. 为每次探索建立动作清单，区分只读、低风险写入和高风险写入。
5. 浏览器取证目录与正式文档目录隔离，认证信息不得写入脚本或命令历史。

### 17.2 操作顺序

1. 先完成路由、菜单、Tab、筛选和只读详情。
2. 在点击任何写按钮前，先开启仅记录方法、脱敏路径、状态码和结构的网络捕获。
3. 每次只执行一个写操作，记录操作前状态、确认提示、请求、任务状态和最终结果。
4. 长任务必须等待到稳定终态；发生未知扣费、异常高频请求或不可逆动作时立即停止。
5. 写操作完成后验证回读、积分变化、审计记录和刷新恢复。
6. 测试结束后删除虚构测试数据、关闭会话并确认无后台任务继续运行。

### 17.3 高成本操作保护

- 必须有费用预估和明确确认，不通过猜测点击。
- 必须携带客户端幂等键，避免双击、重试或刷新造成重复任务。
- 必须记录任务创建成功与否，不能只依据按钮状态。
- 必须验证失败释放预留、取消退款和部分成功计费规则。
- 一旦发现无确认直接扣费，停止同类按钮探索并转为代码/接口只读分析。

### 17.4 证据脱敏

1. 请求和响应只保存结构化字段名、类型、枚举和虚构样例。
2. 删除认证头、Cookie、用户标识、组织标识、业务 ID、动态积分和内部资源地址。
3. 截图必须遮挡账号区、积分区、标题、正文、主体名称和可识别媒体内容。
4. 文件名不得包含真实项目名或业务 ID。
5. 正式文档写入前执行凭据、JWT、账号、UUID、手机号、邮箱、对象存储路径和长随机串扫描。
6. 原始证据只保留在受限本地目录，不进入正式提交。

### 17.5 停止条件

出现任一条件时立即停止写操作并保存脱敏诊断信息：

- 无费用提示却准备创建高成本任务。
- 页面显示真实生产数据或非测试人员信息。
- 权限边界不明确或收到 403 后仍尝试绕过。
- 同一错误请求短时间高频重复。
- 操作可能删除、发布、审核或覆盖不可恢复数据。
- 无法确认任务是否已创建、取消或仍在后台运行。

## 18. 探索完成定义

只有同时满足以下条件，才可将“全平台探索”标记为完成：

### 18.1 页面与控件

- [ ] 所有可达路由均有页面级 E1 证据、入口来源和返回路径。
- [ ] 每页主要控件至少覆盖默认、禁用、加载、成功、空、错误和无权限中的适用状态。
- [ ] 所有高风险控件均有确认、取消、重复点击和失败恢复证据。

### 18.2 流程与状态机

- [ ] 普通漫剧至少有一次成功端到端闭环和一次可控失败闭环。
- [ ] 新闻播报至少有一次成功端到端闭环和一次取消/失败闭环。
- [ ] 每种异步任务均有创建、排队、运行、成功、失败、取消和重试的适用状态证据。
- [ ] 费用预留、结算、释放和返还与任务状态一致。

### 18.3 API 与数据

- [ ] 所有核心读写接口均有脱敏请求/响应契约、错误码和幂等说明。
- [ ] 前端 UI 约束与后端校验逐项对齐。
- [ ] 版本、排序、裁剪、选择和审核等持久化数据可刷新回读。
- [ ] 所有标为 `E2` 的字段和枚举都能追溯到证据；`D` 字段和枚举能追溯到设计决策、约束与验收，不把二者混写。

### 18.4 权限与安全

- [ ] 至少覆盖平台管理员、组织/部门管理者、普通创作者、审核角色和只读角色。
- [ ] 每个角色的页面、按钮、接口和数据范围一致。
- [ ] 认证过期、越权访问、上传安全、下载授权和审计日志已验证。
- [ ] 正式文档和提交内容通过敏感信息扫描，不含原始证据。

### 18.5 响应式与质量

- [ ] 至少覆盖宽桌面、小桌面、平板和手机四类视口。
- [ ] 复杂表格、画布、时间线和弹窗在各视口无重叠或不可达控件。
- [ ] 完成键盘、焦点、对比度、多浏览器、弱网和性能基线验证。
- [ ] 所有 U 项已补证，或由产品负责人明确接受为已知缺口。

## 19. 当前完成度结论

当前证据足以支持：

- 平台信息架构和核心页面清单。
- 剧本、资产、画布、分镜、视频和积分的主要 UI 规格。
- 一批读接口字段、状态枚举和明显技术风险。
- AI 复刻的第一版产品需求、页面原型和领域模型草案。

当前证据不足以支持：

- 宣称普通漫剧从创建到导出已完整成功实测。
- 宣称新闻播报七阶段和最终成片已直接实测。
- 宣称管理员权限矩阵已经验证。
- 宣称存在独立发布或多渠道分发功能。
- 将所有写接口、计费、审核、持久化和异常恢复视为最终契约。
- 宣称已覆盖响应式、可访问性、多浏览器和性能验收。

综上，本轮可判定为“核心只读页面与既有数据探索完成，写流程、新闻闭环、管理权限、发布能力和跨设备质量仍待补证”，尚未达到第 18 节定义的全平台探索完成标准。

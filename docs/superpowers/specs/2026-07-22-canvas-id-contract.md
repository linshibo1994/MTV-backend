# 画布 ID 契约修复

## 目标

修复创作画布保存时，前端生成的 `ent-node-<UUID>` 超过后端 PostgreSQL
`VARCHAR(36)` 限制并导致接口持续返回 500 的问题。

## 约束

- 数据库节点 ID、边 ID 及边端点统一扩展为 `VARCHAR(255)`，复合外键保持同名、同语义。
- 旧 `ent-node-<UUID>` 节点与 React Flow 组合边 ID 必须原样可读写，不能在客户端偷偷改写服务端基线。
- 新主体节点直接使用主体 UUID；新建自由节点和边使用完整 UUID，避免短随机 ID 的全局主键碰撞。
- 后端所有写入画布 ID 列的请求字段限制为 1 到 255 字符，非法输入在数据库操作前返回 422。
- 降级存在超过 36 字符的数据时必须显式拒绝，禁止截断。
- 保存响应经过服务端规范化后，不得被误判为新的本地编辑而连续提交；请求期间真实发生的编辑仍需补交。
- 不覆盖前后端工作区中的既有用户改动。

## 验收标准

1. 新主体节点、新建自由节点和边均使用 36 位 UUID。
2. 旧 45 字符前缀节点及长组合边可原样保存，超过 255 字符返回 422。
3. Alembic 升级后相关四列均为 255，复合外键仍有效。
4. 存在长 ID 数据时，迁移降级明确失败且不改变 revision。
5. 前后端专项测试、类型检查和静态检查通过。
6. 单次编辑保存成功后请求停止；只有请求期间又发生本地编辑且合并后仍有差异时才继续保存。

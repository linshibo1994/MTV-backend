# 生图链路可靠性修复 Spec

## 目标

修复生图任务在创建前、供应商调用、画布保存及前端重试展示中的已确认问题，使历史 enrich 数据与新数据都可稳定创建任务，并让用户获得可操作的失败信息。

## 约束

- 保留后端与前端仓库现有未提交改动，不回滚、不覆盖、不提交无关文件。
- 不读取或修改 `.env*`、密钥、证书与生产配置。
- 数据库仅执行向后兼容的字段扩容迁移，不删除或重写业务数据。
- API 不暴露供应商原始响应、密钥、内部存储键或其他敏感诊断信息。
- 前端继续使用每次新建请求唯一的 `Idempotency-Key`；对失败任务的“重试”必须创建新请求，不能复用旧失败任务。

## 范围

1. 统一 enrich 十二段 prompt 的规范化与校验，兼容 `1. 【标题】` 等历史编号格式。
2. 新生成的 enrich prompt 明确禁止 Markdown 编号，并在持久化边界规范化。
3. Google 生图正确传递 `1K/2K/4K`，`banana-2` 使用 Google 官方当前稳定模型。
4. Worker 记录结构化异常日志，对外仍返回安全、分类后的错误信息。
5. 将画布节点/边相关 ID 列从 36 扩容到 128，兼容 `ent-node-<UUID>` 等前端 ID。
6. 前端展示后端业务错误；失败重试生成新的幂等键并发起新任务。

## 验收标准

- 编号与未编号的十二段 prompt 都能通过同一份共享契约；乱序、缺段、空正文仍被拒绝。
- 历史编号 prompt 无需数据回填即可创建生图任务。
- Google provider 测试断言 `image_size="2K"` 与 `aspect_ratio="16:9"` 同时传递。
- `banana-2` 默认使用 Google 官方当前稳定的 `gemini-3.1-flash-image`，显式配置仍可覆盖。
- Provider/storage 异常会写入后端日志，但 API 不泄露原始异常内容。
- Alembic upgrade/downgrade 定义为无损长度变更，并通过模型/迁移测试。
- 前端针对 409 业务错误显示具体原因，重试使用新幂等键。
- 后端专项测试、Ruff、Mypy；前端相关测试、类型检查/构建及真实浏览器目标流程验证通过。

# 剧本五阶段流水线分钟级优化 Spec

## 目标

- 将 `upload-and-split?auto=true` 的典型两集、约 30 个视觉主体流水线从十几分钟降到数分钟。
- 消除 Enrich 严格文本格式校验造成的误拒、整批回滚和重复模型调用。
- 在不破坏输入版本栅栏、积分结算和主体发布一致性的前提下，引入有界并发、结果复用和可见进度。
- 降低流水线状态轮询的 SQL 数量及历史 `output_json` 加载开销。

## 约束

- 不读取或修改 `.env`、密钥、生产配置、CI/CD 和数据库迁移。
- 测试不得访问真实 LLM、对象存储或付费服务。
- 拆分完成前不能对尚未确定的分集做正式提取；拆分后的各集可以并发提取。
- 关闭的是易误拒的内容格式校验；仍保留最小 JSON 结构、主体类型和 ID 归属安全校验。
- 并发必须有上限，避免触发供应商限流或压垮数据库连接池。

## 设计

1. Enrich
   - 取消固定十二段标题的强制校验，改为宽松、尽力归一化。
   - 视觉主体使用有界并发调用；单主体失败时使用基础 prompt 降级，不重跑整批。
   - 复用 `enrich_version` 未变化的已完成 prompt，并持久化批次进度/检查点。
2. Split / Extract / Merge / Parents
   - 明确集标题可被本地规则可靠识别时，本地拆分；否则保留一次 LLM 拆分。
   - 分集提取使用有界并发，结果按集号稳定排序。
   - Merge 默认使用确定性去重基线，避免再次发送完整剧本；保留可选模型增强能力。
   - Parent 默认使用确定性分组，避免把全部主体再次发送给模型。
3. 状态与可观测性
   - 进度更新可被独立轮询连接及时观察。
   - 叶子任务成功时间与 finalizer 等待时间分离；兄弟叶失败时不把已成功叶伪装成执行失败。
   - 状态查询使用轻量列查询/禁用无关关系加载，不读取历史大 `output_json`。

## 验收标准

- 30 个视觉主体的 Enrich 首轮模型调用数不超过 30；单主体格式异常不触发整批重试。
- Extract 的并发峰值不超过配置上限，输出顺序和阶段明细稳定。
- 已有可复用 prompt 的主体不调用模型。
- 本地可确定 split、merge、parents 路径不调用 LLM。
- `pipeline-status` 查询不重复级联加载 Script 全对象图。
- 相关专项测试、完整 pipeline 测试、Ruff 和 Mypy 通过。
- 未实测真实模型时，性能收益只标记为基于现有调用耗时的预期值。

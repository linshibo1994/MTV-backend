# 视频任务首次创建响应修复 Spec

## 目标

修复 `POST /v3api/video-generation-jobs` 首次创建已成功提交、但响应序列化因
`updated_at` 触发异步隐式加载而返回 500 的问题，确保首次请求直接返回 201。

## 约束

- 保持任务、积分预扣、幂等绑定与事务 outbox 的原子提交语义不变。
- 不通过关闭时间戳自动更新或全局修改 SQLAlchemy 会话策略规避问题。
- 只刷新响应所需且已被服务端 `onupdate` 标记过期的字段，避免覆盖内存中的其他任务数据。
- 不覆盖或回滚当前工作区已有的无关改动。

## 验收标准

1. 首次创建任务提交后，返回 ORM 对象的 `updated_at` 已加载，Pydantic 序列化不会触发隐式数据库访问。
2. 首次请求只创建一个任务、一笔积分预扣和一个 outbox 投递，并可直接返回完整 `VideoJobOut`。
3. 使用相同幂等键重放仍返回同一任务，不产生重复副作用。
4. 使用不同幂等键请求同一活动镜头组仍复用现有任务。
5. 视频生成专项测试与相关 Ruff 检查通过。

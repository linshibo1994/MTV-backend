# 批量生图限流治理 Spec

## 目标

修复一次批量创建大量 `qwen-image` 生图任务时，Celery 并发调用百炼接口触发 HTTP 429，
导致同批任务大面积失败的问题。

## 已确认事实

- 2026-07-23 11:16（Asia/Shanghai）的 30 个任务被同一轮发布。
- Celery worker 并发为 10。
- 百炼同步多模态生图接口返回 2 次 HTTP 200、28 次 HTTP 429。
- 当前生图任务 `max_retries=0`，百炼 Provider 对 429 直接抛错，任务立即终态失败。

## 约束

- 保留批量接口的一次提交与整批幂等语义，不要求前端拆成多次请求。
- 不修改或输出任何 API Key。
- 不覆盖当前工作区与本任务无关的未提交改动。
- 单图创建仍即时入队；批量创建仅对任务发布时间做错峰。
- 只重试明确可恢复的 429/部分 5xx，不重试参数、鉴权或内容策略错误。

## 方案

1. 批量任务按每组 2 个错峰进入 outbox，组间隔 5 秒。
2. outbox 持久化 `available_at`，确保服务重启后仍保留错峰计划。
3. 百炼 Provider 对 HTTP 429 使用带抖动的指数退避有限重试，并尊重 `Retry-After`。
   其他错误不自动重试，避免非幂等 POST 在响应不确定时产生重复计费。
4. 保留最终失败清算逻辑；达到重试上限后仍释放积分并记录失败。

## 验收标准

- 30 个批量任务的 outbox `available_at` 每 2 个为一组，组间至少相差 5 秒。
- 单图任务的 outbox 仍立即可发布。
- 百炼 Provider 遇到 429 后会等待并重试，成功后正常返回图片。
- 百炼 Provider 遇到 400/401/5xx 等其他错误时不重试。
- 相关 Pytest、Ruff 通过。

## 0. 平台总览

| 项 | 值 |
|---|---|
| 平台名 | 智绘 (Flow App) |
| 域名 | `https://zhihui.yangshipin.cn` |
| 前端路由前缀 | `/v3/` |
| 后端 API 前缀 | `/v3api/` |
| 前端形态 | SPA 单 bundle（Vite 构建），入口 `/v3/assets/index-*.js`，路由 hash/history 混合 |
| 后端 | Microsoft IIS/1.1.1，疑似 .NET / ASP.NET |
| 鉴权 | httpOnly Cookie 会话（JS 不可见），登录端点提交后由服务端 `Set-Cookie` |
| 负载均衡 | `tgw_l7_route` cookie（腾讯云 L7 网关，yangshipin.cn 为央视频域名） |
| 产品定位 | 为 AI 影视制作搭建可复制的创作引擎；用可视化画布探索创意，用确定性流程交付作品；把灵感与产出分离，让每一次生成都可追溯、可复用。 |

### 0.1 顶层导航结构

顶部 banner 由三部分组成：

1. **左侧**：智绘 logo（点击回首页）
2. **中部导航按钮**（4 大模块 + 账户区）
   - 剧本页 `/v3/scripts` —— 剧本创作：管理与创作您的剧本故事
   - 资产库 `/v3/asset-library` —— 管理剧本关联的资产集合
   - 创作页 `/v3/materials/<materials_id>/canvas` —— 可视化画布（核心）
   - 视频页 `/v3/videos` —— 按剧本管理视频分镜与剪辑片段
3. **右侧用户区**
   - 当前用户名（如 `chuanbo`）
   - [查看积分明细] 按钮 → 打开积分明细弹窗
   - [退出登录] 按钮

### 0.2 端到端流程（11 步，贯穿全部模块）

```
1. 剧本输入 → 剧集拆分 (split)
2. 每集提取主体 extract（角色/场景/道具/声音 + AI 描述）
3. 跨集合并 merge（去重，如 44 个子主体）
4. 设计线索增强 enrich（扩成摄影级生图 prompt）
5. 归纳父主体 parents（5 个父主体，形态层次）
6. 资产库：生成主体图片候选（GPT Image 2 / Nano Banana）→ 审核 → 通过 1 张为 image_entry；挂载声音资产
7. 创作画布：设计/排布主体图节点
8. 分镜生成：每集 LLM 拆成 场景→镜头组→镜头（含摄影级 prompt + 引用主体 + 配音元素 + 首/尾帧连续性）
9. 视频生成：每镜头组 prompt + 引用主体设计图 → Seedance 2.0 图生视频（异步 job，积分预扣）
10. 时间线编排：片段排序 + trim 裁剪 → 合成最终视频
11. 视频页：按剧本/集管理，查看所有视频
```

## 1. 登录页

### 1.1 路由

- 登录页路由：前端未登录时由全局路由守卫重定向到登录页（具体路径探索笔记未记录，建议 `/v3/login`）
- 未登录访问受保护资源时，API 返回 `401 {"detail":"未登录"}`，前端跳转登录页

### 1.2 UI 元素清单

| 元素 | 类型 | 说明 |
|---|---|---|
| 智绘 logo | 图片/logo | 顶部居中或左对齐 |
| 标题 | 文本 | 如"智绘 Flow App"或"登录" |
| 用户名输入框 | text input | placeholder 如"请输入用户名" |
| 密码输入框 | password input | placeholder 如"请输入密码" |
| 登录按钮 | button(primary) | 提交表单 |
| 错误提示区 | 文本/警示 | 登录失败时显示服务端 `detail` 消息 |

> 注：探索笔记未记录登录页的确切表单字段与登录端点路径。基于 httpOnly Cookie 会话机制，登录端点提交后由服务端 `Set-Cookie` 建立会话，前端不持有 token。复刻时需实现一个 `POST` 登录端点，服务端校验后下发 httpOnly Cookie。

### 1.3 交互行为

1. 用户输入用户名 + 密码，点击 [登录] 按钮
2. 前端 POST 登录请求（建议 `POST /v3api/auth/login`，body: `{username, password}`）
3. 成功：服务端 `Set-Cookie`（httpOnly 会话 + `tgw_l7_route` 负载均衡 cookie），前端跳转到 `/v3/scripts`（剧本列表页）
4. 失败：显示错误提示（来自响应 `detail` 字段），输入框保留用户名，清空密码
5. 登录后，全局每次 API 请求自动携带 Cookie；若任一请求返回 401，前端重定向回登录页

### 1.4 调用的 API

| 操作 | 方法 | 端点 | 说明 |
|---|---|---|---|
| 登录提交 | POST | `/v3api/auth/login`（推断） | 提交凭据，服务端建立会话 |
| 获取当前用户 | GET | `/v3api/auth/me` | 登录后/页面刷新时调用，返回用户模型 |

### 1.5 状态枚举

- 登录状态：`idle` → `loading` → `success`（跳转）/ `error`（显示错误）

### 2.3 剧本处理流水线

#### 2.3.1 流水线状态 — `GET /v3api/scripts/<id>/pipeline-status`

5 阶段流水线：

| 序号 | 阶段 key | 中文名 | 状态 | 结果文本 | 附加字段 |
|---|---|---|---|---|---|
| 1 | `split` | 剧集拆分 | done | "2 集" | — |
| 2 | `extract` | 提取主体 | done | "2/2 集" | current:2, total:2 |
| 3 | `merge` | 合并主体 | done | "44 个子主体" | — |
| 4 | `enrich` | 设计线索增强 | pending | "" | — |
| 5 | `parents` | 归纳父主体 | done | "5 个父主体" | — |

顶层标志：
- `running: false`（是否有阶段在运行）
- `failed: false`（是否有阶段失败）
- `all_done: false`（是否全部完成）

**流水线含义**：输入整段剧本文本 → 拆分集 → 每集 LLM 提取主体(角色/场景/道具/声音) → 跨集合并去重 → 设计线索增强 → 归纳父主体（把同类子主体聚合，如多集出现的同一角色）。

#### 2.3.2 主体提取状态 — `GET /v3api/scripts/<id>/extract-subjects-status`

```json
{
  "total_episodes": 2,
  "extracted_episodes": 2,
  "all_extracted": true,
  "episodes": [
    {
      "episode_id": "<uuid>",
      "episode_no": 1,
      "title": "第 1 集",
      "extract_status": "succeeded",           // succeeded | pending | failed | running
      "extracted": true
    }
  ],
  "merge_status": "succeeded",                  // succeeded | pending | failed | running
  "merge_job_id": "<uuid>",
  "has_active_merge": false                     // 是否有正在运行的合并任务
}
```

#### 2.3.3 主体提取/合并状态枚举

**extract_status（单集提取状态）**：

| 状态 | 含义 |
|---|---|
| `pending` | 等待提取 |
| `running` | 正在提取 |
| `succeeded` | 提取成功 |
| `failed` | 提取失败 |

**merge_status（合并状态）**：

| 状态 | 含义 |
|---|---|
| `pending` | 等待合并 |
| `running` | 正在合并 |
| `succeeded` | 合并成功 |
| `failed` | 合并失败 |

**pipeline 各阶段 status**：

| 状态 | 含义 |
|---|---|
| `pending` | 未开始 |
| `running` | 运行中 |
| `done` | 已完成 |
| `failed` | 失败 |

#### 2.3.4 提取与合并是异步 job

- `merge_job_id`：合并任务的 job ID
- `has_active_merge`：是否有正在运行的合并任务
- 前端轮询 `extract-subjects-status` 与 `pipeline-status` 更新 UI 状态条

#### 2.3.5 调用的 API

| 操作 | 方法 | 端点 | 说明 |
|---|---|---|---|
| 获取剧本 | GET | `/v3api/scripts/<id>` | 剧本元数据 |
| 获取分集列表 | GET | `/v3api/scripts/<id>/episodes` | 所有分集 |
| 获取分集 breakdown | GET | `/v3api/scripts/<id>/episodes/<eid>/breakdown` | 分集主体+镜头 |
| 保存分集 | PUT/PATCH | `/v3api/scripts/<id>/episodes/<eid>`（推断） | 保存剧本文本，触发重新提取 |
| 流水线状态 | GET | `/v3api/scripts/<id>/pipeline-status` | 5 阶段流水线 |
| 主体提取状态 | GET | `/v3api/scripts/<id>/extract-subjects-status` | 提取+合并状态（轮询） |
| 新闻播报任务 | GET | `/v3api/scripts/news-broadcast/jobs` | 特殊剧本类型/模板 |

### 3.3 资产审核弹窗

#### 3.3.1 触发方式

在资产库详情页主体表格中，点击某主体的 [审核资产] 按钮，弹出审核弹窗。

#### 3.3.2 UI 元素清单

| 元素 | 类型 | 说明 |
|---|---|---|
| 弹窗标题 | 文本 | "<主体名> 的候选资产" |
| 图片审核区 | section | 图片候选审核 |
| [通过图片] 按钮 | button(primary) | 选中候选后启用，点击则该候选成为 `image_entry` |
| 图片候选列表 | list | 每条候选 |
| 候选缩略图 | 图片 | 候选图片缩略 |
| 候选状态标签 | badge | "待审" |
| [从审核队列删除] 按钮 | button(icon) | 从候选队列移除 |
| 声音审核区 | section | 声音候选审核 |
| [通过声音] 按钮 | button(primary) | 选中候选后启用 |
| 声音候选列表 | list | 候选列表 或 "暂无候选" |
| 声音候选条目 | 音频播放器 | 候选音频播放 |

#### 3.3.3 交互行为

1. 打开弹窗，加载该主体的图片候选列表和声音候选列表
2. **图片审核流程**：
   - 浏览图片候选缩略图
   - 选中一张候选 → [通过图片] 按钮启用
   - 点击 [通过图片] → 该候选成为主体的 `image_entry`（已通过图片资产），主体 `review_status` 变为 `approved`
   - 点击候选的 [从审核队列删除] → 移出候选队列
3. **声音审核流程**：
   - 浏览声音候选
   - 选中一个 → [通过声音] 按钮启用
   - 点击 [通过声音] → 该候选挂载为 `audio_entries`
   - 若无候选，显示"暂无候选"

#### 3.3.4 核心概念：主体 → 资产转化

```
1. 剧本提取出主体(character/scene/background/prop/sound) + AI 描述
2. 主体归纳父/子(形态)层次
3. 每个主体可生成图片候选 → 审核 → 通过 1 张为 image_entry
4. 每个主体可挂载声音资产(音频文件) audio_entries
5. "去设计" 跳转创作页, 在画布中用这些资产生成镜头/视频
```

#### 3.3.5 调用的 API

| 操作 | 方法 | 端点（推断） | 说明 |
|---|---|---|---|
| 获取候选列表 | GET | `/v3api/scripts/<id>/asset-library/subjects/<subject_id>/candidates` | 图片+声音候选 |
| 通过图片 | POST | `/v3api/scripts/<id>/asset-library/subjects/<subject_id>/approve-image` | 设为 image_entry |
| 删除候选 | DELETE | `/v3api/scripts/<id>/asset-library/subjects/<subject_id>/candidates/<candidate_id>` | 移出队列 |
| 通过声音 | POST | `/v3api/scripts/<id>/asset-library/subjects/<subject_id>/approve-audio` | 挂载 audio_entries |

> 注：审核弹窗的确切端点路径探索笔记未记录，复刻时需按上述语义实现。

## 6. 积分明细弹窗

### 6.1 触发方式

顶部用户区点击 [查看积分明细] 按钮，打开"我的积分明细"弹窗。

### 6.2 积分账户 — `GET /v3api/credits/accounts`

```json
[
  {
    "id": "<account_id>",
    "owner_type": "user",                     // user | org | department
    "owner_id": "<user_id>",
    "org_id": "<uuid>",
    "department_id": "<uuid>",
    "balance_points": 130015,                 // 余额
    "frozen_points": 28980,                   // 冻结(进行中任务预扣)
    "status": "active",                       // active | disabled
    "disabled_reason": null,
    "disabled_at": null,
    "created_at": "...",
    "updated_at": "..."
  }
]
```

- 账户按 owner 挂载（user/org/department）
- 双字段：余额 + 冻结
- 顶部显示"可用积分" = `balance_points - frozen_points`（如 130015 - 28980 = 101035）

### 6.3 积分流水 — `GET /v3api/credits/logs?account_id=<account_id>&limit=N`

```json
[
  {
    "id": "<uuid>",
    "account_id": "<account_id>",
    "actor_user_id": "<uuid>",
    "actor_username": "chuanbo",              // 操作者
    "target_user_id": "<uuid>",
    "target_username": "chuanbo",             // 被操作账户归属
    "reservation_id": "<uuid>",               // 预扣预约ID (冻结/结算关联)
    "source_type": "generation_job",           // generation_job | manual | admin_grant | ...
    "source_id": "<job_id>",                   // 关联任务ID
    "log_type": "settle",                      // settle | reserve | release | grant | refund
    "points_delta": -784,                     // 余额变动(负=消耗)
    "frozen_delta": -210,                     // 冻结变动
    "balance_after": 130015,                  // 操作后余额
    "frozen_after": 28980,                     // 操作后冻结
    "note": null,
    "created_at": "..."
  }
]
```

### 6.4 计费三段式（异步任务积分预扣）

```
1. reserve 冻结: 任务启动时按预估预扣 → frozen_points 增加 (可用减少, 余额不变)
2. settle 结算:  任务完成按实际消耗结算 → points_delta(负, 实际扣余额), frozen_delta(负, 释放冻结)
3. release/refund 释放/返还: 任务失败/取消 → 释放冻结 (返还到余额)
```

- 支持组织/部门代付：actor ≠ target（管理员为下属账户操作）

### 6.5 log_type 枚举

| log_type | 含义 | 方向 |
|---|---|---|
| `reserve` | 冻结（预扣） | frozen 增加 |
| `settle` | 结算（实际扣费） | points 负, frozen 释放 |
| `release` | 释放（取消/失败） | frozen 减少 |
| `grant` | 下发（正向） | points 正 |
| `refund` | 返还（正向） | points 正 |

### 6.6 source_type 枚举

| source_type | 含义 |
|---|---|
| `generation_job` | 生成任务消耗 |
| `manual` | 手动操作 |
| `admin_grant` | 管理员下发 |
| ... | 其他 |

# 智绘 (Flow App) 端到端视频制作流程文档

> 平台域名: https://zhihui.yangshipin.cn
> 前端路由前缀: `/v3/`
> 后端 API 前缀: `/v3api/`
> 定位: 为 AI 影视制作搭建可复制的创作引擎 — 用可视化画布探索创意, 用确定性流程交付作品。

本文档以"把一段剧本文本变成一支成片"为主线, 逐步骤详解端到端 11 步主流程。每步包含: 目的、触发入口、用户操作、后端处理、调用的 API、产出物、状态流转、积分消耗点。文末附关键概念解释与复刻开发验收清单。

## 1. 流程总览与层级结构

### 1.1 端到端 11 步主流程

| 步骤 | 名称 | 阶段归属 | 核心动作 | 产出物 |
|------|------|----------|----------|--------|
| 1 | 创建剧本 | 剧本模块 | 输入整段剧本文本 | Script + Episode |
| 2 | 剧集拆分 split | AI 流水线 | LLM 将全文拆为多集 | 多个 Episode (含 script_text) |
| 3 | 提取主体 extract | AI 流水线 | 每集 LLM 提取角色/场景/道具/声音 + AI 描述 | 主体 Subject 列表 (is_child=true) |
| 4 | 合并主体 merge | AI 流水线 | 跨集子主体去重 | 去重后的子主体集合 (示例: 44 个) |
| 5 | 设计线索增强 enrich | AI 流水线 | 将简单描述扩成摄影级生图 prompt | 主体 design prompt (含布光/材质/构图/锁) |
| 6 | 归纳父主体 parents | AI 流水线 | 把同类子主体聚合为父主体/形态 | 父主体列表 (示例: 5 个) |
| 7 | 资产库生图审核 | 资产库模块 | 生图模型生成候选图片 -> 人工审核 -> 通过 1 张为 image_entry; 挂载声音资产 | image_entry + audio_entries |
| 8 | 创作画布设计 | 创作页模块 | 画布上排布主体设计图节点, 一键设计/生图设置/提交审核 | Materials 画布项目 + 节点 |
| 9 | 分镜生成 | 视频页模块 | 每集 LLM 拆 场景 -> 镜头组 -> 镜头 (含摄影级 prompt + 引用主体 + 配音 + 首尾帧) | Shot Hierarchy (scenes/groups/shots) |
| 10 | 视频生成 | 视频页模块 | 每镜头组 prompt + 引用主体设计图 -> Seedance 2.0 图生视频 | 视频片段 (每片段=一个镜头组) |
| 11 | 时间线编排 | 视频页模块 | 片段排序 + trim 裁剪 -> 合成成片 | 最终视频 |

### 1.2 数据层级结构

```
Script (剧本)
  └── Episode (集, 含 script_text)
       ├── Subjects (主体: character/scene/prop/sound, is_child, parent_id)
       │    └── Asset (image_entry 图片资产 + audio_entries 声音资产)
       ├── Scenes (背景场景, scene_no)
       │    └── Shot Groups (镜头组, = 视频生成单元)
       │         ├── prompt (多镜头分时段组合)
       │         ├── reference_frames (first/last/reference_frame)
       │         ├── materials (引用的主体资产)
       │         ├── audio_elements (需配音角色)
       │         └── Shots (镜头, 含 content + description)
       └── Video Generation Jobs (每镜头组一个 job)
            └── Timeline Arrangement (排序 + trim)
```

### 1.3 模块与路由对照

| 模块 | 前端路由 | 后端 API 基础路径 |
|------|----------|-------------------|
| 剧本页 | `/v3/scripts`, `/v3/scripts/<id>/episodes/<eid>` | `/v3api/scripts/` |
| 资产库 | `/v3/asset-library`, `/v3/asset-library/<script_id>` | `/v3api/scripts/<id>/asset-library/` |
| 创作页 (画布) | `/v3/materials/<materials_id>/canvas` | `/v3api/materials/` |
| 视频页 | `/v3/videos`, `/v3/videos/<script_id>` | `/v3api/shots/`, `/v3api/video-generation-jobs`, `/v3api/video-timeline-arrangements` |
| 积分/账户 | 顶部用户区 [查看积分明细] | `/v3api/credits/`, `/v3api/auth/` |

## 2. 前置: 用户与积分体系

### 2.1 用户模型

| 字段 | 说明 |
|------|------|
| `username` | 用户名 |
| `user_id` | 用户唯一 ID (UUID) |
| `is_admin` | 是否管理员 |
| `account_type` | `personal` (个人) / `team` (团队) |
| `org_id` | 所属企业 ID |
| `department_id` | 所属部门 ID |
| `management_scope` | 账户管理范围: `none` / `department` / `org` |
| `organizations` | 所属企业列表 (含 org_name, org_code) |

- 多租户模型: 用户 -> 部门(department) -> 企业(org)
- 鉴权: httpOnly Cookie 会话 (JS 不可见), 登录端点提交后由服务端 Set-Cookie
- 负载均衡: `tgw_l7_route` cookie (腾讯云 L7 网关)
- 401 未登录响应: `{"detail":"未登录"}`

### 2.2 积分账户模型

| 字段 | 说明 |
|------|------|
| `owner_type` | `user` / `org` / `department` |
| `owner_id` | 归属 ID |
| `balance_points` | 可用余额 |
| `frozen_points` | 冻结积分 (预扣/进行中任务占用) |
| `status` | `active` / `disabled` |

- 顶部显示"可用积分" = `balance_points` - `frozen_points`
- 积分账户按 owner 维度挂载, 支持组织/部门代付

### 2.3 计费三段式 (异步任务积分预扣)

| 阶段 | log_type | 说明 | balance 变化 | frozen 变化 |
|------|----------|------|--------------|-------------|
| 1. 冻结 | `reserve` | 任务启动时按预估预扣 | 不变 | 增加 (可用减少) |
| 2. 结算 | `settle` | 任务完成按实际消耗结算 | 减少 (实际扣余额) | 减少 (释放冻结) |
| 3. 释放/返还 | `release` / `refund` | 任务失败/取消, 返还冻结 | 不变 | 减少 (返还到可用) |

- 积分流水 `source_type`: `generation_job` / `manual` / `admin_grant` 等
- 积分明细 UI 三 Tab: 已获取 (grant, 正向) / 已消耗 (consume, 负向) / 已返还 (refund, 正向)
- 积分由 department (部门) 下发给用户 -> 部门/组织额度分配模型

### 2.4 计费对象 (消耗积分的操作)

| 操作 | 模型/服务 | 典型消耗 |
|------|-----------|----------|
| 主体提取/合并/增强 | LLM | 较小 |
| 主体设计图生成 | GPT Image 2 / Nano Banana (banana-2) | 中等 |
| 分镜生成 | LLM | 较小 |
| 视频生成 | Seedance 2.0 (doubao-seedance-2-0-260128) | 主要消耗 (示例: 每次 ~784~994 积分 + 冻结 210) |

## 步骤 1: 创建剧本并输入文本

### 目的
创建一个剧本项目, 录入整段剧本文本, 作为后续所有 AI 处理的输入源。

### 触发入口
- 剧本列表页 `/v3/scripts` -> 点击 [新建剧本] 按钮

### 用户操作
1. 在剧本列表页点击 [新建剧本]
2. 输入剧本标题 (如"末日丧尸·小猪")
3. 选择 scope: `personal` (个人项目) 或 `team` (团队项目)
4. 进入剧本详情编辑器 `/v3/scripts/<script_id>/episodes/<episode_id>` (默认进第 1 集)
5. 在主区左侧大文本域中输入/粘贴整段剧本文本
6. 可通过左栏 [新增一集] 管理集数 (双击改集数, 可删除)
7. 点击顶部 [保存] 按钮 (dirty 时启用)

### 后端处理
- 创建 Script 记录: 含 id, title, scope, owner_user_id, org_id (个人项目为 null), created_by_user_id, created_at, updated_at
- 创建/关联 Episode 记录: 含 episode_id, script_id, episode_no, title ("第 N 集"), episode_version (乐观锁版本号, 初始为 1), schema_version, client_save_seq
- 保存剧本文本到 episode.script_text (script_file_storage_key 为 null 表示文本内联存储; 也支持对象存储 key)
- 保存时递增 episode_version 和 client_save_seq (乐观并发控制)

### 调用的 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/v3api/scripts/page?limit=30&offset=0&scope=personal` | 剧本列表 (scope=personal/team) |
| POST | `/v3api/scripts` (推断) | 创建剧本 |
| GET | `/v3api/scripts/<id>` | 获取剧本详情 |
| GET | `/v3api/scripts/<id>/episodes` | 获取分集列表 |
| POST/PUT | `/v3api/scripts/<id>/episodes/<eid>` (推断) | 保存剧本文本 |
| GET | `/v3api/scripts/<id>/episodes/<eid>/breakdown` | 获取分集拆解 (含 episode + subjects + shots + shot_groups, 此处 shots/shot_groups 为空) |

### 产出物
- Script 记录 (id, title, scope, owner 等)
- 至少一个 Episode 记录 (含 script_text 剧本文本)

### 状态流转
- Episode 初始状态: episode_version=1, client_save_seq=1
- 保存后: dirty 标记清除, episode_version 递增

### 积分消耗点
- 无 (纯文本录入不消耗积分)

## 步骤 2: 剧集拆分 split

### 目的
将整段剧本文本通过 LLM 自动拆分为多个剧集 (Episode), 使后续处理能按集粒度进行主体提取与分镜。

### 触发入口
- 剧本详情页编辑器中, 保存剧本文本后自动触发 (或手动触发流水线)
- 剧本流水线状态接口返回 split 阶段

### 用户操作
1. 录入并保存剧本文本后, 系统自动启动 AI 流水线
2. 前端通过状态条展示流水线进度 (如"剧集拆分: 2 集")
3. 用户等待流水线完成, 可在编辑器左栏看到拆分出的集数列表

### 后端处理
- LLM 分析全文结构, 按场景/章节/叙事节点拆分为多集
- 为每集创建/更新 Episode 记录, 填入对应的 script_text 片段
- 写入流水线状态: split 阶段 = done, 产出 "N 集"
- episode_version 递增

### 调用的 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/v3api/scripts/<id>/pipeline-status` | 获取流水线 5 阶段状态 |
| GET | `/v3api/scripts/<id>/episodes` | 获取拆分后的分集列表 |
| GET | `/v3api/scripts/<id>/episodes/<eid>/breakdown` | 获取某集拆解详情 |

### pipeline-status 返回结构
```json
{
  "stages": [
    {"stage": "split", "status": "done", "result": "2 集"},
    {"stage": "extract", "status": "done", "result": "2/2 集", "current": 2, "total": 2},
    {"stage": "merge", "status": "done", "result": "44 个子主体"},
    {"stage": "enrich", "status": "pending", "result": ""},
    {"stage": "parents", "status": "done", "result": "5 个父主体"}
  ],
  "running": false,
  "failed": false,
  "all_done": false
}
```

### 产出物
- 多个 Episode 记录 (每集含独立的 script_text)
- pipeline-status 中 split 阶段标记 done

### 状态流转
- pipeline: split: pending -> running -> done
- Episode: 新增集记录, episode_version 更新

### 积分消耗点
- LLM 调用消耗积分 (主体提取/合并/增强类操作, 较小)

## 步骤 3: 提取主体 extract

### 目的
对每集剧本文本, 通过 LLM 提取主体 (Subject): 角色 (character)、场景 (scene/background)、道具 (prop)、声音 (sound), 并为每个主体生成 AI 描述 (详细外观/音色说明, 可直接用作生图/配音 prompt)。

### 触发入口
- split 阶段完成后自动触发
- 剧本编辑器状态条显示 "主体提取: N/N 集"

### 用户操作
1. split 完成后, 系统自动逐集执行 extract
2. 前端轮询 extract-subjects-status, 展示进度
3. 编辑器主区右侧主体面板逐步显示提取出的主体卡片
4. 编辑器主区左侧剧本文本中, 主体按类型高亮 (4 类型过滤: 角色/场景/道具/声音)
5. 主体卡片展示: 类型标签 + 名称 + 出现集数 (如"1·2集") + [删除] + AI 描述

### 后端处理
- 对每集 episode.script_text 调用 LLM, 提取主体
- 为每个主体生成 description (AI 生成的详细外观/音色说明)
- 创建 Subject 记录: id, type, name, description, is_child=true, episode_nos (出现的集号列表)
- 异步 job, 前端轮询状态 (类似 merge_job_id 机制)
- 写入 pipeline-status: extract 阶段, current/total 跟踪进度

### 调用的 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/v3api/scripts/<id>/extract-subjects-status` | 获取提取状态 (含每集 extract_status, merge_status, merge_job_id) |
| GET | `/v3api/scripts/<id>/episodes/<eid>/breakdown` | 获取该集的主体列表 (subjects 数组) |

### extract-subjects-status 返回结构
```json
{
  "total_episodes": 2,
  "extracted_episodes": 2,
  "all_extracted": true,
  "episodes": [
    {"episode_id": "...", "episode_no": 1, "title": "第 1 集",
     "extract_status": "succeeded", "extracted": true}
  ],
  "merge_status": "succeeded",
  "merge_job_id": "<uuid>",
  "has_active_merge": false
}
```

### Subject 模型
```json
{
  "id": "<uuid>",
  "type": "character|scene|prop|sound",
  "name": "保安丧尸",
  "description": "男性丧尸，身穿破烂的保安服。面部狰狞，嘴角挂着不明液体，体态扭曲踉跄。",
  "is_child": true,
  "episode_nos": [1, 2]
}
```

### 主体类型枚举

| type | 含义 | 备注 |
|------|------|------|
| `character` | 角色 | 人物 |
| `scene` / `background` | 场景 | 背景环境 (breakdown 用 scene, 资产库用 background) |
| `prop` | 道具 | 物品 |
| `sound` | 声音 | 配音音色/音效 |

### 产出物
- 每集的 Subject 列表 (is_child=true), 含 AI 描述
- pipeline-status: extract 阶段 done, result "N/N 集"

### 状态流转
- 每集 extract_status: pending -> running -> succeeded
- pipeline: extract: pending -> running -> done

### 积分消耗点
- LLM 调用消耗积分 (主体提取/合并/增强类)

## 步骤 4: 合并主体 merge

### 目的
跨集对子主体进行去重合并, 将多集中重复出现的同一主体合并为一个, 形成全局唯一的子主体集合 (示例: 44 个子主体)。

### 触发入口
- extract 阶段全部集完成后自动触发
- 异步 job (merge_job_id), 前端轮询

### 用户操作
1. extract 完成后, 系统自动启动 merge job
2. 前端通过 extract-subjects-status 中的 merge_status / merge_job_id 轮询
3. 合并完成后, 主体面板展示去重后的全局主体列表
4. 用户可在主体面板中查看合并后的主体 (含跨集 episode_nos)
5. 可双击编辑主体名/描述, 可删除主体

### 后端处理
- 创建异步 merge job (merge_job_id)
- LLM 比对跨集主体的名称与描述, 判定是否为同一主体
- 合并同一主体: 合并 episode_nos, 统一 name/description
- 合并后子主体 is_child=true, 尚无 parent_id
- 写入 pipeline-status: merge 阶段 done, result "N 个子主体"

### 调用的 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/v3api/scripts/<id>/extract-subjects-status` | 轮询 merge_status, merge_job_id, has_active_merge |
| GET | `/v3api/scripts/<id>/episodes/<eid>/breakdown` | 获取合并后该集的主体列表 |
| GET | `/v3api/scripts/<id>/asset-library/subjects?limit=200&offset=0` | 获取全部合并后主体 (资产库视角) |

### 产出物
- 去重后的全局子主体集合 (示例: 44 个, is_child=true)
- pipeline-status: merge 阶段 done, result "44 个子主体"

### 状态流转
- merge_status: pending -> running -> succeeded
- has_active_merge: true (运行中) -> false (完成)
- pipeline: merge: pending -> running -> done

### 积分消耗点
- LLM 调用消耗积分 (主体提取/合并/增强类)

## 步骤 5: 设计线索增强 enrich

### 目的
将主体的简单描述 (如"男性丧尸, 身穿破烂的保安服") 扩展为专业摄影级生图 prompt, 包含形制描述、材质钉死、使用痕迹、摆放姿态、反悬浮锁、时代锚定、画面构图、画风统一锁、三点柔光箱白底布光、反水印锁、文字渲染降级方案、写实质感锚定等段落, 作为后续生图/生视频的关键输入。

### 触发入口
- merge 阶段完成后自动触发
- pipeline-status 中 enrich 阶段

### 用户操作
1. merge 完成后, 系统自动启动 enrich
2. 前端状态条展示 enrich 进度 (示例中为 pending, 即待生成视觉设计线索)
3. enrich 完成后, 主体的 design prompt 可在创作画布节点中查看 (node.data.prompt)

### 后端处理
- LLM 对每个主体的 name + type + description 进行 prompt 扩展
- 扩展模板 (道具/场景版) 含段落:
  - 形制描述
  - 材质钉死
  - 使用痕迹
  - 摆放姿态
  - 反悬浮锁
  - 时代锚定
  - 画面构图
  - 画风统一锁
  - 三点柔光箱白底布光
  - 反水印锁
  - 文字渲染降级方案
  - 写实质感锚定 (Phase One 中画幅 + 100mm 微距 + f/8)
- 扩展后的 prompt 存储为主体/节点的 design prompt
- 写入 pipeline-status: enrich 阶段 done

### 调用的 API

| 方法 | 路径 | 说明 |

## 步骤 6: 归纳父主体 parents

### 目的
将同类子主体聚合为父主体 (parent subject), 体现"形态"概念 — 即同一主体的不同表现形态 (如同一角色在不同集的服装/状态差异), 或同类道具的不同样式。示例: 5 个父主体, 每个父主体下有若干子主体 (形态)。

### 触发入口
- enrich 阶段完成后自动触发 (或与 enrich 并行)
- pipeline-status 中 parents 阶段

### 用户操作
1. 系统自动归纳父主体
2. 完成后在资产库详情页可见: 行按父主体分组, 标题如"安全区（2 个形态）""酱料罐（2 个形态）"
3. 分组末尾"其余子主体（N）" = 无父主体的子主体
4. 用户可在资产库中调整父/子归属 (推断)

### 后端处理
- LLM 分析子主体的相似性, 聚合同类主体为父主体
- 父主体: is_parent=true, parent_id=null, 有 child_count
- 子主体: is_child=true, parent_id 指向父主体
- 写入 pipeline-status: parents 阶段 done, result "N 个父主体"

### 调用的 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/v3api/scripts/<id>/pipeline-status` | 轮询 parents 阶段状态 |
| GET | `/v3api/scripts/<id>/asset-library/parent-subjects` | 获取父主体列表 |
| GET | `/v3api/scripts/<id>/asset-library/subjects?limit=200&offset=0` | 获取全部主体 (含 parent_id, is_parent, parent_name) |

## 步骤 7: 资产库生成主体图片候选并审核通过

### 目的
为每个主体 (角色/场景/道具) 生成图片候选, 人工审核通过 1 张作为该主体的 image_entry (已通过图片资产); 为声音主体挂载声音资产 (audio_entries)。这是"主体 -> 资产"转化的核心步骤。

### 触发入口
- 资产库详情页 `/v3/asset-library/<script_id>`
- 剧本编辑器顶部 [查看资产库] 按钮
- 创作画布右侧栏 [去审核] 按钮

### 用户操作
1. 进入资产库详情页, 看到统计: 已审核数量 / 未审核数量 / 全部主体数量 (示例: 2 / 35 / 37)
2. 表格按父主体分组, 列: 图片 | 主体名 | 主体类别 | 描述 | 声音 | 所属集数 | 资产审核 | 审核状态 | 操作
3. 对图片类主体:
   a. 点击 [审核资产] 打开审核弹窗 ("<主体名> 的候选资产")
   b. 图片审核区: 候选列表 (每条: 缩略图 + "待审" + [从审核队列删除])
   c. 选中候选后点击 [通过图片] -> 该图成为 image_entry
   d. 或删除候选将其移出队列
4. 对声音类主体:
   a. 声音审核区: [通过声音] + 候选列表 ("暂无候选" 或已有候选)
   b. 或直接在表格声音列挂载声音资产 (上传音频文件)
5. 可双击编辑主体名/描述; 主体类别下拉可改 (角色/场景/道具/声音); 所属集数下拉可改

### 后端处理
- 生图模型生成候选图片 (banana-2 = Google Nano Banana / Gemini 2.5 Flash Image; gpt-image-2 = GPT Image 2 / OpenAI)
- 候选图片进入审核队列 (pending_candidate)
- 人工审核:
  - 通过 -> 候选变为 image_entry (单个, primaryImageIndex=0)
  - 删除 -> 移出队列
- 声音资产挂载为 audio_entries (多个)
- 更新 review_status: not_designed -> pending -> approved

### 调用的 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/v3api/scripts/<id>/asset-library/subjects?limit=200&offset=0` | 获取全部主体 (含 review_status, image_entry, audio_entries) |
| GET | `/v3api/scripts/<id>/asset-library/parent-subjects` | 获取父主体列表 (分组用) |
| GET | `/v3api/scripts/<id>/asset/entries?limit=1&offset=0` | 获取资产计数 (列表页用) |
| POST | (推断) 生图接口 | 生成图片候选 |
| POST | (推断) 审核接口 | 通过/删除候选, 挂载声音 |

### 资产审核状态枚举

| review_status | review_status_label | 含义 |
|---------------|---------------------|------|
| `not_designed` | 未通过 | 未设计/未通过, 无 image_entry |
| `pending` | 未审核 | 有待审候选 (pending_candidate_count > 0) |
| `approved` | 已通过 | 有 image_entry |

### 产出物
- 每个图片类主体的 image_entry (已通过图片资产, 单个)
- 每个声音类主体的 audio_entries (声音资产, 多个)
- review_status: approved 的主体可用于后续分镜/视频生成

### 状态流转
- 主体审核: not_designed -> (生成候选) -> pending -> (人工通过) -> approved
- pending_candidate_count: 0 -> (生成) -> N -> (审核) -> 0

### 积分消耗点
- 主体设计图生成 (GPT Image 2 / Nano Banana): 中等消耗
- 注: 此步骤与步骤 8 (创作画布) 紧密关联, 画布的"一键设计"即批量生成候选, "一键提交审核"即批量提交到审核队列

## 步骤 8: 创作画布设计排布主体节点

### 目的
在可视化画布 (基于 React Flow) 上为每个主体生成 + 管理设计图, 排布节点便于统一审视风格一致性。这是"主体设计画布", 节点 = 主体设计图; 真正的镜头/视频合成在后续分镜流程。

### 触发入口
- 资产库详情页 [去设计] 按钮
- 后端: GET `/v3api/scripts/<script_id>/canvas-project/ensure` -> 返回/创建 materials_id -> 前端跳转 `/v3/materials/<materials_id>/canvas`

### 用户操作
1. 点击 [去设计], 系统确保/创建 materials 画布项目并跳转
2. 画布顶部工具栏节点类型: 文本 / 图片 (GPT Image 2) / 选择分镜 / 上传 / Assets
3. 画布交互: Zoom In/Out, Fit View, Toggle Interactivity, Mini Map; 节点可拖动 (方向键移动), Delete 删除, Esc 取消
4. 右侧栏主体设计队列:
   - 统计: 44/44 (全部 / 未设计 N / 可审核 N / 已通过 N)
   - 集数筛选下拉: 全部集数 / 第1集(35) / 第2集(41)
   - [一键设计 N] 批量为未设计主体生成图 (消耗积分)
   - [生图设置] 模型/尺寸/比例/风格等生图参数
   - [一键提交审核 N] 批量提交可审核主体到审核队列
   - 主体按类型分组: 角色(10) / 道具(12) / 背景(14) / 声音(8)
5. 每个主体行操作:
   - 图片类未设计: "设计 X" -> 创建绑定图片节点 (挂到画布并触发生图)
   - 图片类可审核: "前往 X 匹配资产" -> 跳资产库审核
   - 声音类: "上传 X 声音" -> 创建绑定声音节点 (上传音频)
6. 节点移动/增删/参数变更通过增量保存提交

### 后端处理
- 创建/获取 Materials 画布项目: id, name, script_id, created_at, updated_at
- 画布状态: nodes + edges (React Flow 格式)
- 节点创建时自动构造 prompt: 固定模板 + 主体名/类型/描述 + "要求：主体清晰、特征稳定、背景干扰少、适合后续多图参考生成"

- 生图完成后: imageOutputs 数组 (含 status, assetId, storageKey), primaryImageIndex 指定主选图

## 步骤 9: 分镜生成

### 目的
对每集, 通过 LLM 将剧本文本拆分为层级结构: 场景 (Scenes) -> 镜头组 (Shot Groups) -> 镜头 (Shots)。每镜头含摄影级结构化 description; 每镜头组含多镜头分时段组合 prompt + 引用主体 + 配音元素 + 首尾帧连续性。

### 触发入口
- 视频页详情 `/v3/videos/<script_id>?tab=storyboard-video&episode=<episode_id>`
- 点击 [分镜生成] 按钮: "只为当前选中集生成分镜结果"

### 用户操作
1. 进入视频页, 左栏选择集 (第1集/第2集...)
2. 点击 [分镜生成] 按钮
3. 系统对当前选中集执行 LLM 分镜拆分
4. 分镜结果区展示每条分镜 (镜头) 缩略与描述
5. Tab 切换: [分镜结果] [镜头组合并]
6. 分镜视频 Tab 内查看层级: 场景 -> 镜头组 -> 镜头

### 后端处理
- LLM 分析 episode.script_text, 按叙事结构拆分
- 层级: Episode -> Scenes (按背景场景聚合, scene_no) -> Shot Groups (镜头组, group_no 如 G1) -> Shots (镜头, shot_no, display_no)
- 每镜头生成:
  - content: 镜头画面内容 (自然语言)
  - description: 摄影级结构化描述 = 在【背景】采用【机位】视角 + 画面主体【角色】+ 关键动作【】+ 整体画面【】+ 表达情绪【】+ 光影效果【】+ 叙事目的【】
- 每镜头组生成:
  - prompt: 多镜头分时段组合 (【镜头1:0~4s】【镜头2:4~7s】...) + 【角色】+ 【叙事目的】+ 【约束】
  - reference_frames: {first_frame, last_frame, reference_frame} (首帧/尾帧/参考帧, 用于片段间连续性, 尾帧 -> 首帧衔接)
  - shots: 该组内的镜头列表
- scene_key = "bg:<背景名>" (场景按背景主体聚合)

| POST | (推断) 分镜生成接口 | 触发 LLM 分镜 |
| GET | `/v3api/shots/<script_id>/cover` | 获取视频项目封面 (首个镜头首帧) |

- 【镜头N:起~止s】场景是X, 景别·机位, 运镜 (固定/推轨/拉轨), 光影, 画面动作, 情绪, 【角色名】:台词
- 【角色】列出引用主体
- 【叙事目的】
- 【约束】人物特征一致/不脸崩/不畸形/切镜丝滑/4K稳定/语音清晰/唇形动作对位/禁字幕

- 每镜头组的 materials (引用的主体资产) 与 audio_elements (需配音角色)

- Episode breakdown 的 shots/shot_groups: 空 -> 有数据

## 步骤 10: 视频生成

### 目的
对每个镜头组 (Shot Group, = 视频生成单元), 将其 prompt + 引用的主体设计图 (作为多参考图) 送入 Seedance 2.0 图生视频模型, 生成视频片段。支持批量、变体、检查素材、参考帧。

- 对每个镜头组触发视频生成 (或批量触发)

### 用户操作
1. 在视频工作台中选择镜头组
2. 系统自动汇聚该镜头组引用的主体设计图作为 reference_images
3. 触发视频生成 (推断: 点击生成按钮或批量生成)
4. 前端轮询 video-generation-jobs 状态/进度
5. 生成完成后, 视频片段可用于时间线编排

## 关键概念解释

### 1. 父主体 / 子主体与形态

- **子主体 (child subject)**: `is_child=true`, 是从单集提取出的、具体的主体实例 (如"第1集的保安丧尸"和"第2集的保安丧尸"可能是两个子主体)
- **父主体 (parent subject)**: `is_parent=true`, `parent_id=null`, 是跨集合并后同类子主体的聚合 (如"保安丧尸"父主体下有 2 个形态)
- **形态**: 父主体下的每个子主体代表一种"形态" — 即同一主体的不同表现形态 (如同一角色在不同集的服装/状态差异, 或同类道具的不同样式)
- **资产库分组**: 行按父主体分组, 标题如"安全区（2 个形态）"; 无父主体的子主体归入"其余子主体（N）"
- **去重合并**: merge 阶段将多集中重复的子主体合并, parents 阶段将同类子主体聚合为父主体

### 2. 镜头组作为视频生成单元

- **镜头组 (Shot Group)**: 多个镜头 (Shot) 合并为一个视频片段生成, 是视频生成的最小单元
- **unit_id**: `group:<shot_group_id>`, 标识生成单元
- **unit_runtime_key**: `<runtime>:<scene_no>:group:<group_id>`, 运行时键 (关联时间线编排)
- **prompt**: 多镜头分时段组合 (【镜头1:0~4s】【镜头2:4~7s】...), 一个 prompt 生成一段包含多镜头切换的视频
- **duration_seconds / video_duration_seconds**: 视频时长 (如 7 秒)
- 一个镜头组生成的视频片段 = 时间线上的一个片段

### 3. reference_frames 连续性

- **reference_frames**: `{first_frame, last_frame, reference_frame}` — 首帧/尾帧/参考帧
- **用途**: 保证片段间 (镜头组之间) 的视觉连续性, 前一片段的尾帧 (last_frame) 作为后一片段的首帧 (first_frame) 参考
- **初始状态**: 分镜生成时为 null (尚未生成视频)
- **填充时机**: 视频生成完成后, 从生成结果中提取首帧/尾帧填入
- **连续性链**: 场景内多个镜头组依次衔接, 尾帧 -> 首帧形成连续画面

### 4. materials 自动汇聚参考图

- **materials** (在 video-workbench 中): 该镜头组引用的所有主体资产, 按类型分组:
  - `character`: 引用的角色主体名列表
  - `background`: 引用的背景主体名列表
  - `prop`: 引用的道具主体名列表
  - `other`: 其他
- **自动汇聚**: 系统按 shot_group.prompt 中引用的主体名, 自动取其已通过的设计图 (image_entry) 作为 reference_images
- **reference_image_names**: 与 reference_images 一一对应, 标明每张参考图对应的主体名 (如 ["手机","王贵发","郊外荒地-外-夜"])
- 即: prompt 提到哪些主体 -> materials 列出 -> 自动取设计图 -> 作为多参考图送入视频模型

### 5. all_reference 多参考

- **job_type: all_reference**: 多参考图生视频模式
- **reference_images**: 多张参考图 (各主体的设计图), 每张含 storage_key, mime_type, size_bytes, sha256
- **reference_audios**: 可选, 参考音频 (声音资产)
- **reference_videos**: 可选, 参考视频
- **模型**: doubao-seedance-2-0-260128 (Seedance 2.0), 支持多参考图输入, 生成保持主体特征一致的视频
- **多 provider**: jianyu / modelsai, 全局可通过 active-provider 切换

### 6. 积分三段式计费

- **reserve (冻结)**: 任务启动时按预估预扣, frozen_points 增加 (可用减少, 余额不变)
- **settle (结算)**: 任务完成按实际消耗, 余额减少, 冻结减少
- **release/refund (释放/返还)**: 任务失败/取消, 冻结返还到可用
- **流水字段**: log_type, points_delta, frozen_delta, balance_after, frozen_after, reservation_id (冻结/结算关联), source_type (generation_job), source_id (job_id)

## 复刻开发要点与验收清单

### 前端开发要点

1. **技术栈**: SPA 单 bundle (Vite 构建), React + React Flow (画布), hash/history 混合路由, 路径前缀 `/v3/`

1. **技术栈**: 疑似 .NET / ASP.NET (IIS/1.1.1), API 前缀 `/v3api/`

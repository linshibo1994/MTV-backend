# 研究方法与证据等级

> 本文档定义对央视频「智绘 (Flow App)」平台逆向调研所采用的方法论、证据等级体系与事实写作规则。
> 配合 `01`–`06` 实测文档使用：那些文档描述平台现状，本文规定"如何采信与表述"。

---

## 1. 研究目标

形成一套可直接指导 AI / 工程师从零复刻开发的规格，而非界面观感描述。研究必须覆盖：

1. 信息架构、页面与导航关系。
2. 用户角色、权限与数据可见范围。
3. 从剧本到视频的完整业务流程与状态机。
4. 页面控件、字段、默认值、校验、空态、错误态与异步状态。
5. 领域实体、接口契约、任务轮询、计费与并发控制线索。
6. 可执行的验收标准、异常用例与非功能要求。

工作区中的外部采集记录覆盖剧本页 / 资产库 / 创作页 / 视频页 / 积分账户模块，详见 `01-产品需求文档-PRD.md` 至 `06-AI能力与Prompt工程文档.md`。

---

## 2. 证据等级

| 等级 | 定义 | 可用于什么 | 不能用于什么 |
| --- | --- | --- | --- |
| `E1` | 截图、可重复页面操作直接确认 | 页面结构、可见文本、控件、局部状态 | 截图外的隐藏行为、未点击后的流程 |
| `E2` | 网络请求 / API 响应或操作笔记；需保留来源并能重放 | 字段结构、接口路径、状态枚举、数据模型 | 宣称前端必然按某方式渲染，或把来源不明记录当作当前线上事实 |
| `E3` | 基于 E1/E2 的合理推导 | 解释业务意图、提出验证假设 | 当作原平台明确需求 |
| `D` | 为复刻产品提出的推荐设计 | 架构、容错、安全、可维护性改进 | 描述原平台现状 |
| `U` | 尚无证据 | 形成待验证问题 | 进入确定性需求或验收结论 |

> 注：只有 `exploration/screenshots/` 中可见的页面内容可直接列为 `E1`。其余本地记录在当前会话完成浏览器重放前保持 `E2 候选`；供应商品牌解释和架构推断保持 `E3` 或 `D`。

## 4. 证据采集规范

每个页面至少应采集以下证据；外部记录声称已执行的项目仍需当前会话重放抽查：

1. 路由与页面可访问性快照（a11y tree，含控件 uid）。
2. 完整可见文本与控件清单。
3. 初始 / 加载 / 空 / 成功 / 失败 / 禁用状态中实际可达的状态。
4. 关键动作执行前后的页面变化。
5. 对应网络请求的方法、脱敏 URL、状态码、请求字段与响应结构。
6. 异步任务：首次响应、轮询、状态迁移、完成与失败响应。
7. 不可逆动作（发布/删除/付费/上传）：只记录提交前确认弹窗与字段，不点击最终确认。

## 5. 事实写作规则

- "存在""支持""会自动"等确定性表述必须有 `E1` 或已复核的 `E2` 证据。
- 由字段名推断的业务语义使用"可能""推测""待验证"。
- 推荐实现使用"复刻建议"，不得混入原平台现状段落。
- 示例数据全部使用 `<uuid>`、`<account_id>`、`1000` 等虚构值，不暴露真实账号、积分与业务文本。
- 凭据、Cookie、令牌不写入任何文档。

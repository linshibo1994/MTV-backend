## 1. 总体架构

### 1.1 架构总览(文字描述)

智绘平台采用"前端 SPA + 后端 API 网关 + 对象存储代理 + AI 供应商"四层架构, 自顶向下的调用链如下:

```
┌─────────────────────────────────────────────────────────────────────┐
│                        终端用户浏览器                                 │
│          https://zhihui.yangshipin.cn/v3/  (前端 SPA)                │
└────────────┬──────────────────────────────┬─────────────────────────┘
             │ HTTPS (httpOnly Cookie)       │ 图片/视频媒体流
             ▼                               ▼
┌──────────────────────────┐   ┌──────────────────────────────────────┐
│  /v3api/ 后端 API 层       │   │  sapi.yangshipin.cn 对象存储代理       │
│  (IIS/1.1.1, 疑似 ASP.NET) │   │  /api/x/cctv/zhihui/flow-app/...      │
│  RESTful JSON              │   │  鉴权代理 → 底层对象存储                 │
└─────┬──────────┬───────────┘   └───────────────┬──────────────────────┘
      │          │                                │
      │ AI 调用   │ 积分/任务/DB                     │ 读写生成结果
      ▼          ▼                                ▼
┌──────────┐  ┌──────────────────┐  ┌────────────────────────────────┐
│ AI 供应商  │  │ 数据库 + 任务队列   │  │  对象存储(底层, 如 COS/OSS)       │
│ (见 1.2)  │  │ (乐观锁/版本控制)   │  │  generate_images/ upload_images  │
└──────────┘  └──────────────────┘  └────────────────────────────────┘
```

### 1.2 四层职责划分

| 层级 | 组件 | 职责 |
|------|------|------|
| 前端 SPA | Vite 构建 React SPA, 路由前缀 `/v3/` | 画布渲染(React Flow)、表单交互、轮询任务状态、增量 delta 提交 |
| 后端 API | IIS/1.1.1 上的 ASP.NET 服务, 前缀 `/v3api/` | 业务逻辑、鉴权、任务调度、积分预扣/结算、AI 供应商编排、对象存储鉴权代理签发 |
| 对象存储代理 | `sapi.yangshipin.cn` 子域 | 图片/视频媒体读写代理, 路径 `/api/x/cctv/zhihui/flow-app/`, 隔离底层存储并统一鉴权 |
| AI 供应商 | LLM、文生图、视频生成模型 | 提供 AI 能力, 由后端统一调度, 前端不直连 |

### 1.3 AI 供应商矩阵

| 能力类别 | 模型标识 | 实际模型 | Provider / 调用方 |
|----------|----------|----------|-------------------|
| LLM 文本理解 | (未显式暴露模型名) | 疑似通用大语言模型 | 后端编排, 用于 split/extract/merge/enrich/parents/分镜 |
| 文生图(主体参考图) | `banana-2` | Google Nano Banana (Gemini 2.5 Flash Image) | 后端编排 |
| 文生图(海报/封面) | `gpt-image-2` | OpenAI GPT Image 2 | 后端编排 |
| 视频生成 | `doubao-seedance-2-0-260128` | 字节豆包 Seedance 2.0 | provider: `jianyu` 或 `modelsai` |

### 1.4 核心设计原则

1. **灵感与产出分离**: 前端画布承载创意探索(非确定性), 后端流水线承载交付(确定性流程)。
2. **异步任务化**: 所有 AI 调用封装为 job, 前端轮询 status/progress, 积分预扣。
3. **多租户隔离**: 用户→部门→企业的组织树, 数据与积分按 owner 维度隔离。
4. **乐观并发控制**: episode_version / client_save_seq / schema_version 多重版本号。
5. **对象存储代理统一鉴权**: 前端永不直连底层存储, 全部经 sapi 代理。

## 2. 前端技术栈

### 2.1 构建与产物

| 项 | 说明 |
|----|------|
| 构建工具 | Vite, 输出**单 bundle** SPA |
| 入口产物 | `/v3/assets/index-*.js` (hash 命名, 由 `/v3/` 提供) |
| 路由模式 | hash / history 混合, 全部前缀 `/v3/` |
| 部署 | 静态资源由 IIS 或网关直接提供, 无 SSR |

### 2.2 核心前端库

| 库 | 用途 |
|----|------|
| **React Flow** | 创作页可视化节点画布(`/v3/materials/<materials_id>/canvas`), 渲染主体设计图节点、拖拽、连线、Mini Map、Fit View、Zoom |
| React(推断) | SPA 框架基础 |
| 受控表单模式 | 剧本编辑器、资产审核弹窗、生图设置均为受控表单(同步表单状态与后端模型) |

### 2.3 前端路由表

| 路由 | 模块 | 说明 |
|------|------|------|
| `/v3/scripts` | 剧本列表 | 个人/团队 Tab, 搜索, 新建 |
| `/v3/scripts/<sid>/episodes/<eid>` | 剧本详情编辑器 | 分集管理 + 剧本文本 + 主体面板 |
| `/v3/asset-library` | 资产库列表 | 每剧本一卡片 |
| `/v3/asset-library/<sid>` | 资产库详情 | 主体资产表, 审核 |
| `/v3/materials/<mid>/canvas` | 创作画布 | React Flow 画布, 主体设计队列 |
| `/v3/videos` | 视频列表 | 按剧本管理 |
| `/v3/videos/<sid>?tab=...` | 视频详情 | 分镜视频 / 所有视频 Tab |

### 2.4 会话与请求

- **会话凭证**: httpOnly Cookie, JS 不可见, 由服务端 `Set-Cookie` 下发; 前端不持有 token, 所有请求自动携带 Cookie。
- **未登录判定**: 后端返回 401 `{"detail":"未登录"}`, 前端拦截跳登录。
- **错误体约定**: 所有错误为 JSON `{"detail": "<message>"}`。

### 2.5 关键交互模式

- **任务轮询**: 创建 generation-job / video-generation-job 后, 前端按周期轮询 `GET /v3api/generation-jobs/<id>` 与 `GET /v3api/video-generation-jobs?...`, 读取 `status / progress / progress_stage / progress_message` 更新 UI(节点上的 `isGenerating`、进度条)。
- **增量保存**: 画布节点移动/增删/参数变更以 delta 形式 `POST /v3api/materials/<mid>/canvas/delta` 提交。
- **确定性封面**: 资产库列表卡片封面用按标题确定性生成的 3 段线性渐变 SVG + 高斯模糊占位图(`data:image/svg+xml`), 无需后端图片。

## 3. 后端技术栈

### 3.1 服务器与运行时

| 项 | 值 / 说明 |
|----|----------|
| Web 服务器 | `IIS/1.1.1`(Microsoft IIS) |
| 应用框架(推断) | ASP.NET (基于 IIS 托管与 JSON 风格推断) |
| 请求/响应 | RESTful, JSON, UTF-8 |
| API 前缀 | `/v3api/` |
| 错误响应 | HTTP 4xx/5xx + `{"detail": "<message>"}` |

### 3.2 API 风格

- **RESTful 资源化路径**, 典型形态:
  - 列表分页: `GET /v3api/scripts/page?limit=30&offset=0&scope=personal`
  - 资源详情: `GET /v3api/scripts/<id>`
  - 子资源: `GET /v3api/scripts/<id>/episodes`
  - 状态端点: `GET /v3api/scripts/<id>/pipeline-status`
  - 幂等 ensure: `GET /v3api/scripts/<script_id>/canvas-project/ensure`
- **查询参数**: limit/offset 分页, scope=personal|team, account_id 过滤, script_id/episode_id 过滤。
- **列表响应**: `{"items":[...]}` 或 `{"items":[...], ...元数据}`。

### 3.3 推断的后端模块(按资源域)

| 资源域 | 代表端点 |

| 资产库 | `/v3api/scripts/<id>/asset-library/subjects`, `/v3api/scripts/<id>/asset-library/parent-subjects`, `/v3api/scripts/<id>/asset/entries` |
| 画布 | `/v3api/materials/<id>`, `/v3api/materials/<id>/canvas`, `/v3api/materials/<id>/canvas/delta`, `/v3api/materials/<mid>/image/<image_id>` |

## 4. 鉴权与多租户

### 4.1 会话机制

- **凭证**: httpOnly Cookie(登录端点提交后由服务端 `Set-Cookie`)。
- **安全属性**: httpOnly → JS 不可读, 防 XSS 窃取; 前端不持有任何 token。
- **未登录响应**: `401 {"detail":"未登录"}`。
- **负载均衡会话粘性**: `tgw_l7_route` cookie(腾讯云 L7 网关), 保证会话路由一致。

### 4.2 多租户模型

```
用户(User) ──属于──> 部门(Department) ──属于──> 企业(Organization)
```

| 字段 | 说明 |
|------|------|
| `user_id` | 用户唯一 ID(UUID) |
| `username` | 用户名 |
| `account_type` | `personal` / `team` |
| `org_id` | 所属企业 ID |
| `department_id` | 所属部门 ID |
| `is_admin` | 是否管理员 |
| `can_manage_accounts` | 是否可管理积分账户 |
| `management_scope` | `none` / `department` / `org`, 账户管理范围 |
| `organizations[]` | 用户可访问的企业列表(`id`, `org_name`, `org_code`) |

### 4.3 数据隔离

- 剧本 `scope`: `personal`(个人项目, `org_id=null`) / `team`(团队项目, 带 `current_user_project_role` 协作角色)。
- 积分账户按 `owner_type`(user/org/department) + `owner_id` 挂载, 自然隔离。
- 团队项目带 `current_user_project_role`, 控制单项目内协作权限。

## 5. 异步任务架构

### 5.1 两类 Job 体系

| Job 类别 | 端点 | 典型 job_type |
|----------|------|---------------|
| 生成任务(图片/LLM) | `/v3api/generation-jobs/<job_id>` | `generate_images` |
| 视频生成任务 | `/v3api/video-generation-jobs?script_id=&episode_id=` | `all_reference` |

### 5.2 Job 状态模型

```json
{
  "job_id": "<uuid>",
  "material_id": "<uuid>",          // generation-jobs 关联画布
  "script_id": "<uuid>",            // video-generation-jobs 关联剧本
  "episode_id": "<uuid>",
  "scene_no": 1,
  "job_type": "generate_images|all_reference",
  "status": "succeeded",            // starting|processing|succeeded|failed|canceled
  "progress": 100,                  // 0-100
  "progress_stage": "succeeded",   // 阶段标识
  "progress_message": "success",
  "error_message": null,
  "input_json": "{...}"             // 序列化的输入参数(prompt, resolved_prompts, reference_images...)
}
```

### 5.3 任务状态轮询约定

| 字段 | 用途 |
|------|------|
| `status` | 生命周期状态, 前端判断终态 |
| `progress` | 0-100 百分比, 进度条 |
| `progress_stage` | 子阶段名(如 succeeded), 细粒度展示 |
| `progress_message` | 人可读阶段消息 |
| `error_message` | 失败时原因 |

前端按周期轮询; 建议复刻时对轮询做节流(见 9.3), 终态后停止轮询。

### 5.4 积分预扣三段式(reserve-settle-release)

异步任务的生命周期与积分账户的冻结/结算强绑定:

```
任务启动
   │
   ▼ 1. reserve(冻结)
   │  按预估从 balance_points 预扣到 frozen_points
   │  (可用 = balance - frozen 减少, 余额不变)
   │
   ▼ 任务执行中 ...
   │
   ├──── 成功 ──> 2. settle(结算)
   │              points_delta = -实际消耗 (扣余额)
   │              frozen_delta  = -释放冻结
   │              balance_after / frozen_after 更新
   │
   └──── 失败/取消 ──> 3. release/refund(释放/返还)
                        frozen_delta = -释放冻结 (返还可用)
```

| log_type | 含义 | points_delta | frozen_delta |
|----------|------|--------------|-------------|
| `reserve` | 冻结预扣 | 0 | +预估 |
| `settle` | 结算实际消耗 | -实际 | -释放冻结 |
| `release` / `refund` | 释放/返还 | 0 | -释放冻结 |
| `grant` | 下发(部门→用户) | +N | 0 |

- **流水字段**: `actor_user_id`/`actor_username`(操作者), `target_user_id`/`target_username`(被操作账户归属), `reservation_id`(冻结/结算关联 ID), `source_type`(如 `generation_job`), `source_id`(关联 job_id)。
- **支持代付**: actor ≠ target, 管理员为下属账户操作。
- **积分来源**: 部门(department)下发给用户, 形成组织额度分配模型。
- **消耗场景**: 主体提取/合并/增强(LLM)、主体设计图生成(文生图)、分镜生成(LLM)、视频生成(Seedance, 主要消耗, 单次约 784~994 积分 + 冻结 210)。

## 6. 对象存储与媒体代理

### 6.1 代理域名与路径

| 项 | 值 |
|----|----|
| 代理域名 | `sapi.yangshipin.cn` |
| 路径前缀 | `/api/x/cctv/zhihui/flow-app/` |
| 底层存储 | 对象存储(如腾讯云 COS, 经代理隔离) |

### 6.2 存储路径分类

两类存储路径, 对应两种来源:

| storage_key 形态 | 来源 | 说明 |
|------------------|------|------|
| `/generate_images/<materials_id>/<image_id>.png` | AI 文生图 | 模型生成结果 |
| `/upload_images/<materials_id>/<image_id>.png` | 用户上传 | 上传的图片/视频/音频 |

> 注: 视频生成任务的 `reference_images` 中 `storage_key` 同时出现 `generate_images` 与 `upload_images` 前缀, 说明参考图可来自生成或上传。

### 6.3 图片寻址流程

1. 画布节点 `imageOutputs[].storageKey` = `/generate_images/<mid>/<id>.png`
2. 前端获取元数据: `GET /v3api/materials/<mid>/image/<image_id>` →
   ```json
   {"image_id":"<uuid>","storage_key":"/generate_images/<mid>/<id>.png",
    "mime_type":"image/png","size_bytes":2411098,"source":"generate_images"}
   ```
3. 拼接实际可访问 URL: `https://sapi.yangshipin.cn/api/x/cctv/zhihui/flow-app/generate_images/<mid>/<id>.png`

### 6.4 鉴权模型

- 前端不直连底层对象存储, 全部经 `sapi` 代理。
- 代理层负责鉴权(基于 httpOnly 主会话或独立签名), 底层存储凭证不暴露给前端。
- 复刻建议: sapi 代理层实现"会话校验 → 签发临时下载 URL / 直接代理流式返回"。

## 7. 增量协同机制

### 7.1 画布增量保存

- 端点: `POST /v3api/materials/<mid>/canvas/delta`
- 用途: 画布节点移动/增删/参数变更以 delta 增量提交, 避免全量覆盖, 协同友好。
- 读取全量: `GET /v3api/materials/<mid>/canvas` → `{"material_id","nodes":[...],"edges":[...]}`

### 7.2 乐观并发控制(多重版本号)

| 字段 | 所在对象 | 作用 |
|------|----------|------|
| `episode_version` | Episode | 分集乐观锁版本号, 每次保存递增 |
| `client_save_seq` | Episode breakdown | 客户端保存序号, 防并发覆盖 |
| `schema_version` | Episode breakdown | 数据结构版本, 兼容性迁移 |

- 保存剧本时携带 `episode_version` / `client_save_seq`, 服务端比对; 不一致则拒绝, 强制客户端刷新后重试。
- `schema_version` 用于数据结构演进, 复刻时应在 DB 设版本字段并实现迁移。

### 7.3 画布项目与剧本的 ensure 约定

- `GET /v3api/scripts/<script_id>/canvas-project/ensure`: 幂等创建/返回 `materials_id`, 一个剧本→一个 materials 画布项目。
- Materials 模型: `{"id","name","script_id","created_at","updated_at"}`。

## 8. AI 能力集成层

### 8.1 AI 流水线总览(端到端)

```
剧本文本
  │
  ▼ 1. split    剧集拆分
  │
  ▼ 2. extract  每集 LLM 提取主体(character/scene/prop/sound + AI 描述)
  │
  ▼ 3. merge    跨集合并去重子主体
  │
  ▼ 4. enrich   设计线索增强(扩成摄影级生图 prompt)         ← 生图关键输入
  │
  ▼ 5. parents   归纳父主体(同类子主体聚合为形态)
  │
  ▼ 6. 资产生成   文生图(banana-2 / gpt-image-2) → 审核 → image_entry
  │
  ▼ 7. 画布设计   创作画布排布主体设计图节点
  │
  ▼ 8. 分镜生成   LLM 拆 场景→镜头组→镜头(摄影级 prompt + 引用主体 + 配音元素 + 首尾帧)
  │
  ▼ 9. 视频生成   镜头组 prompt + 主体设计图(多参考图) → Seedance 2.0 图生视频(异步 job, 积分预扣)
  │
  ▼ 10. 时间线编排 片段排序 + trim 裁剪 → 合成最终视频
```

### 8.2 LLM 能力点

| 阶段 | 输入 | 输出 |
|------|------|------|
| split | 整段剧本文本 | 分集列表(episode_no, title) |
| extract | 单集剧本文本 | 主体列表(type=character/scene/prop/sound, name, description(AI 生成详细外观/音色), episode_nos) |
| merge | 各集主体列表 | 去重后的子主体集合(如 44 个) |
| enrich | 主体简单描述 | 摄影级生图 prompt(见 8.3) |
| parents | 子主体集合 | 父主体聚合(如 5 个, child_count 形态数) |
| 分镜 | 集剧本文本 + 主体资产 | 场景→镜头组→镜头 + 摄影级 prompt + 引用主体 + 配音元素 + 首/尾帧连续性 |

### 8.3 prompt 扩展模板(enrich 产物)

主体设计图节点的 `prompt` 由固定模板 + 主体名/类型/描述 + 通用要求自动构造; 而 generation-job 的 `input_json.resolved_prompts.final` 则是经 LLM 进一步扩展后的超详细摄影级 prompt, 含以下段落:

| 段落 | 内容 |
|------|------|
| 形制描述 | 主体外形 |
| 材质钉死 | 材质确定性约束 |
| 使用痕迹 | 磨损/做旧 |
| 摆放姿态 | 构图姿态 |
| 反悬浮锁 | 防悬浮/失重 |
| 时代锚定 | 年代确定性 |
| 画面构图 | 构图指令 |
| 画风统一锁 | 全集风格一致 |
| 三点柔光箱白底布光 | 摄影棚布光: 三点柔光箱 + 白底 |
| 反水印锁 | 防水印 |
| 文字渲染降级方案 | 文字失败降级 |
| 写实质感锚定 | Phase One 中画幅 + 100mm 微距 + f/8 |

### 8.4 文生图能力

| 模型标识 | 实际模型 | 用途 | 参数 |
|----------|----------|------|------|
| `banana-2` | Google Nano Banana (Gemini 2.5 Flash Image) | 主体参考图(角色/场景/道具) | size=2k, aspect=16:9 |
| `gpt-image-2` | OpenAI GPT Image 2 | 宣传图/海报/封面 | (同上参数体系) |

- 节点 `model` 字段切换模型。
- 可生成多张选一: `imageOutputs[]` + `primaryImageIndex` 主选序号。
- 节点 `variant`: `generated`(生成) / `uploaded`(上传) / `text`(文本) / `storyboard`(分镜)...。

### 8.5 视频生成能力

| 项 | 值 |
|----|----|
| 模型 | `doubao-seedance-2-0-260128`(豆包 Seedance 2.0) |
| provider | `jianyu` / `modelsai`(可切换, `GET /v3api/video-generation/active-provider`) |
| job_type | `all_reference`(多参考图生视频) |
| 生成单元 | 镜头组(shot_group), `unit_id = "group:<shot_group_id>"` |
| unit_runtime_key | `<runtime>:<scene_no>:group:<group_id>` |
| 参考图来源 | 该镜头组 prompt 引用的主体(character/background/prop/other)已通过设计图, 自动汇聚为 `reference_images[]` |
| 参考图元数据 | `{kind:"storage", storage_key, mime_type, size_bytes, sha256}` |
| 参考图名 | `reference_image_names[]`(对应主体名, 如 `["手机","王贵发","郊外荒地-外-夜"]`) |
| 音频参考 | `reference_audios[]` / `reference_audio_names[]`(配音元素) |
| 视频参考 | `reference_videos[]` / `reference_video_names[]` |
| prompt | 镜头组的多镜头分时段组合 prompt |

### 8.6 分镜层级结构(视频生成的前置)

```
Episode(集) → Scene(场景, scene_no) → Shot Group(镜头组, group_no="G1") → Shot(镜头, shot_no/display_no)
```

- **Shot Group**: 视频生成单元, prompt 为多镜头分时段组合(`【镜头1:0~4s】【镜头2:4~7s】...`), 含 `reference_frames: {first_frame, last_frame, reference_frame}` 保证片段间首尾连续性。
- **Shot**: 最小镜头单元, `content`=画面内容, `description`=摄影级结构化描述(背景+机位+主体+动作+画面+情绪+光影+叙事目的)。
- **materials**: 镜头组引用的所有主体资产(character/background/prop/other), 自动作为参考图。
- **audio_elements**: 该组内需配音的角色(关联声音资产)。

### 8.7 视频时间线编排

- 端点: `GET /v3api/video-timeline-arrangements?script_id=&episode_id=`
- 模型: `{id, unit_runtime_key, job_id, row_order, is_selected, trim_start_seconds, trim_end_seconds, ...}`
- 语义: 已生成视频片段(每片段=一个镜头组的 job 产物)按 `row_order` 排列 + `trim_start/end_seconds` 裁入裁出 → 合成最终视频。

## 9. 关键非功能特性

### 9.1 乐观锁与并发

| 机制 | 对象 | 字段 |
|------|------|------|
| 乐观锁 | Episode | `episode_version`(每次保存递增) |
| 客户端保存序号 | Episode breakdown | `client_save_seq`(防并发覆盖) |
| 数据结构版本 | Episode breakdown | `schema_version`(兼容性迁移) |
| 增量协同 | Canvas | delta 增量提交, 避免全量覆盖 |

### 9.2 任务幂等

- `GET .../canvas-project/ensure`: 幂等创建画布项目。
- 积分流水 `reservation_id`: 跨 reserve/settle/release 关联, 保证一致性。
- Job `job_id`(UUID): 全局唯一, 轮询与积分结算的关联键。

### 9.3 轮询节流(复刻建议)

- 前端轮询 generation-jobs / video-generation-jobs 应做退避(如指数退避或固定 2-3s 间隔), 终态停止。
- 列表端点(如 `/video-generation-jobs?limit=500`)单次取大量 job, 避免高频分页。

### 9.4 封面生成

- 资产库列表卡片: 按标题确定性生成 3 段线性渐变 SVG + 高斯模糊占位图(`data:image/svg+xml`), 无后端图片, 零存储成本。
- 视频项目封面: `GET /v3api/shots/<script_id>/cover`, 取自首个镜头的首帧。

## 11. 分层与模块边界建议

### 11.1 推荐分层

| 层 | 职责 | 复刻建议 |
|----|------|----------|
| 网关层 | 路由、会话粘性、TLS、限流 | 腾讯云 L7 或 Nginx, cookie 粘性 |
| 静态资源层 | 前端 SPA 单 bundle | CDN 或 IIS 静态托管, `/v3/assets/*` |
| API 层 | 业务逻辑、鉴权、任务调度、积分、AI 编排 | ASP.NET / 任意后端, RESTful `/v3api/` |
| 对象存储代理层 | 媒体鉴权代理 | sapi 独立服务, 会话校验 + 流式代理 |
| 数据层 | DB + 任务队列 + 积分账本 | 关系型 DB + 乐观锁字段 + 异步队列 |
| AI 编排层 | 供应商抽象、prompt 构造、结果落地 | 独立模块, provider 可切换(如 jianyu/modelsai) |

### 11.2 模块边界(按资源域)

| 模块 | 边界 | 对外端点前缀 | 数据所有权 |
|------|------|-------------|-----------|
| 鉴权模块 | 会话、多租户、权限 | `/v3api/auth/*` | User, Org, Department |
| 积分模块 | 账户、流水、reserve/settle/release | `/v3api/credits/*` | Account, Log, Reservation |
| 剧本模块 | 剧本、分集、流水线、breakdown | `/v3api/scripts/*` | Script, Episode, Subject, Shot |
| 资产库模块 | 主体资产、审核、父主体 | `/v3api/scripts/<id>/asset-library/*` | Subject, AssetEntry, ImageEntry, AudioEntry |
| 画布模块 | Materials、Canvas 节点、delta | `/v3api/materials/*` | Materials, CanvasNode, CanvasEdge |
| 生成任务模块 | generation-jobs | `/v3api/generation-jobs/*` | GenerationJob |
| 分镜模块 | shot-hierarchy、video-workbench、cover | `/v3api/scripts/<sid>/episodes/<eid>/shot-*`, `/v3api/shots/*` | Scene, ShotGroup, Shot |
| 视频生成模块 | video-generation-jobs、provider、timeline | `/v3api/video-generation*`, `/v3api/video-timeline-*` | VideoJob, Provider, TimelineArrangement |
| 媒体代理模块 | 图片/视频读写 | `sapi.yangshipin.cn/api/x/cctv/zhihui/flow-app/*` | 对象存储对象 |

### 11.3 跨模块协作约定

- **剧本→资产库**: 一对一关系, `script_id` 为主键关联。
- **剧本→画布**: ensure 幂等创建, `materials.script_id` 外键。
- **剧本→分镜**: `episode_id` 关联, breakdown 的 `shots/shot_groups` 初始为空, 由分镜生成阶段填充。
- **分镜→视频生成**: 镜头组(`shot_group_id`)为生成单元, `unit_id`/`unit_runtime_key` 贯穿 job 与 timeline。
- **画布→生成任务**: 节点 `generationJobId` 关联 generation-jobs, 节点 `assetId`/`imageOutputs[].assetId` 关联图片资产。
- **任意 AI 任务→积分**: `source_type=generation_job`, `source_id=job_id`, reservation_id 贯穿 reserve/settle/release。

## 12. 复刻开发要点与验收清单

### 12.1 复刻开发要点

1. **前端单 bundle**: 用 Vite 构建单 bundle SPA, 路由统一 `/v3/` 前缀, 不可 SSR。
2. **画布库选型**: 必须采用 React Flow 或等价节点画布库, 支持拖拽/Zoom/Mini Map/Fit View/增量 delta。
3. **httpOnly Cookie 鉴权**: 前端不持 token, 401 `{"detail":"未登录"}` 跳登录, `tgw_l7_route` 会话粘性。
4. **错误体统一**: 所有错误 `{"detail": "..."}`。
5. **异步任务化**: 所有 AI 调用封装为 job, 状态字段 status/progress/progress_stage/progress_message/error_message, 前端轮询。
6. **积分三段式**: reserve(冻结) → settle(结算) / release(释放), reservation_id 关联, 支持 actor≠target 代付。
7. **对象存储代理**: 前端不直连底层存储, 经 `sapi` 代理, 路径 `/api/x/cctv/zhihui/flow-app/`, `generate_images/` 与 `upload_images/` 两类前缀。
8. **乐观锁**: episode_version + client_save_seq + schema_version 三重版本号。
9. **增量协同**: Canvas delta 增量保存, 避免全量覆盖。
10. **AI 供应商可切换**: 视频 provider `jianyu`/`modelsai` 可切换(`active-provider`), 文生图 `banana-2`/`gpt-image-2` 模型可选。
11. **prompt 工程化**: enrich 产物为摄影级 prompt(含布光/锁/材质/画风统一等段落), 分镜 prompt 为多镜头分时段组合 + 连续性首尾帧。
12. **分镜层级**: Episode → Scene → Shot Group → Shot, 生成单元为 Shot Group。
13. **时间线编排**: 片段按 row_order 排列 + trim 裁剪合成。
14. **确定性封面**: 资产库卡片用 SVG 渐变占位, 视频封面取首镜头首帧。
